# 宠物接入指南

本文回答一个问题：**把这个仓库拉下来以后，怎么加一只属于自己的宠物，且不需要改任何源码。**

答案是：一只宠物就是 `pets/` 下的一个文件夹。文件夹里放一个 `pet.yaml` 和若干资源文件，宿主启动时扫描目录、读取清单、渲染它。清单里的每一个字段都由你自己控制，包括配色、感应区、台词、菜单和拖拽响应——**改这些都不需要碰 TypeScript、Vue 或 Rust**。

如果某一项配置写错了，宿主会退回内置默认值继续运行，不会崩溃、不会影响其他宠物。

## 30 秒接入

### 第 1 步：建目录

在仓库的 `pets/` 下新建一个文件夹，**文件夹名就是宠物 ID**：

```
pets/
├── aether_mecha_core/      ← 已内置
├── demo_sprite_pet/        ← 已内置
├── nyx_abyssal_familiar/   ← 已内置
├── pulse_glitch_phantom/   ← 已内置
└── silverfeather_chibi/    ← 已内置（含完整注释，可直接当模板抄）
```

### 第 2 步：放资源

把图片放进这个文件夹。精灵图宠物最少需要一张：

```
pets/silverfeather_chibi/
├── pet.yaml
├── idle.png
├── speaking.png
└── thinking.png
```

### 第 3 步：写 pet.yaml

照抄 `pets/silverfeather_chibi/pet.yaml`，改掉 `id`（必须与文件夹同名）和资源文件名即可。

### 第 4 步：启动

```bash
npm run tauri dev
```

**不需要重启。** 宿主用文件监听器递归监控 `pets/`（300ms 去抖），你保存 `pet.yaml` 的那一刻它就会重新扫描目录；新加整个文件夹也会被自动发现。在桌面上右键 → 「切换机体」，或点状态坞的「换宠物」，就能切到新宠物。

## 目录与命名规则

| 规则 | 说明 | 违反后果 |
| --- | --- | --- |
| 文件夹名 = `pet.yaml` 里的 `id` | 宿主按文件夹名取 ID，不读 YAML 里的 `id` | 两者不一致时以文件夹名为准 |
| ID 只能用 `a-z A-Z 0-9 _ -`，长度 ≤ 64 | Rust 侧 `validate_safe_pet_id` 校验 | 该宠物被跳过，不出现在列表里 |
| 必须有 `pet.yaml` | 没有就跳过整个目录 | 静默忽略 |
| 资源路径相对于该文件夹 | 不要写绝对路径或 `../` | 加载失败，回退到占位图 |

## pet.yaml 字段全解

### 身份

```yaml
id: "silverfeather_chibi"       # 必须与文件夹同名
name: "银羽（Q版）"             # 显示名，出现在切换气泡、伴生舱列表
version: "2.0.0"
type: "sprite"                  # sprite | live2d | spine | vrm
description: "一句话简介"        # 可选
```

### model —— 模型与动作

```yaml
model:
  entry: "idle.png"             # 默认显示的资源
  scale: 1.0                    # 缩放，0.1 ~ 5.0
  offset:
    x: 0
    y: 0
  fps: 60
  animations:                   # 动作名 → 资源
    idle:
      file: "idle.png"
      loop: true
    happy:
      file: "speaking.png"
      loop: false
      duration_ms: 2400
```

**动作名的两种来源**，可以用其中任意一种或混用：

- **宿主内置动作**：`idle` / `happy` / `pat` / `feed` / `drag` / `climb` / `sleep`。
  这些名字在引擎里有专门的程序化表现（`happy` 会弹跳、`pat` 会挤压、`feed` 会脉冲），写进 `animations` 只是指定该动作期间显示哪张图。
- **你自己起的动作名**：任意名字都可以，比如你的宠物有三个状态，就在 `animations` 里写 `idle` / `thinking` / `speaking`，然后在菜单的 `motion` 字段里写 `speaking` 就能切到那张图。自定义动作**没有**程序化特效，只有换图。

想让 `pat`（摸头反应）显示「手指靠脸颊」那张、`sleep`（睡觉）也用同一张，就把两者都指向同一个 `file`——资源文件可以复用。

### expressions —— 表情着色

```yaml
expressions:
  neutral:
    tint: 0xffffff   # 不改变
  smile:
    tint: 0xfff1e6   # 暖色调
  surprised:
    tint: 0xe0f2fe
  sleepy:
    tint: 0xcbd5e1
```

`tint` 是叠加色，十六进制 `0xRRGGBB`。这是**染色**而不是换图：如果你有独立的表情图，可以改用 `file:` 字段。

### theme —— 专属配色（写在清单里，不用改代码）

```yaml
theme:
  id: "silverplume_stream"
  name: "银羽流光 (Silverplume Stream)"
  primary: "#a5b4fc"              # 主色：星盘环、按钮、粒子
  accent: "#f9a8d4"               # 强调色：徽章、中心锁定键
  glow: "rgba(165, 180, 252, 0.55)"   # 发光（要带 alpha）
  surface: "rgba(28, 26, 46, 0.92)"    # 面板底色（要带 alpha）
  border: "rgba(165, 180, 252, 0.6)"   # 描边（要带 alpha）
  text: "#f8fafc"                 # 主文字
  subtext: "#c7d2fe"              # 次文字
  particleColor: "#a5b4fc"
```

**这一段是「不用改代码」的关键。** 配色写在这里，星盘、状态坞、气泡、伴生舱、HUD 会整体跟随。十个字段都可以省略，省略的项会继承内置默认配色。

优先级：清单里的 `theme` > `src/store/themes.ts` 里登记的同名项 > 内置默认。

### persona —— 给这只宠物定制性格（喂给大模型用）

```yaml
persona:
  identity: "你是银羽，一名成年女性 AI 游戏主播。"
  traits:
    - "温柔灵动"
    - "好奇"
    - "略带撒娇但不黏人"
  style_notes: |-
    对直播间统一称「大家」。
    只根据当前画面回答；不确定就直说，不要编造。
```

| 字段 | 作用 |
| --- | --- |
| `identity` | 一句身份介绍，放在提示词开头 |
| `traits` | 性格形容词列表，组装成「你的性格：…」。不写则用中性值「友善、好奇」 |
| `style_notes` | 自由文本：语气、禁忌、对用户的称呼、篇幅要求 |
| `system_prompt` | **直接替换整个提示词**。宠物需要完整人设 brief 时用它，会忽略上面三项 |

四个字段都可以只写一部分；组装出来的提示词始终自带结尾的回复约束（长度、只依据当前画面、不编造）。

**优先级**：`persona.system_prompt` > 界面上填的「自定义人设 Prompt」> 上面三字段组装 > 中性默认值。

这段同样写在清单里，**不需要改代码**。配好之后在伴生舱「网页与AI脑桥」页启用 LLM 即可生效。

### voice —— 让这只宠物用自己的嗓子

宠物可以覆盖宿主的语音设置。**结构与 `config/settings.yaml` 里的 `audio.tts` / `audio.stt`
完全一致**，只是只用写想改的那几个键，其余从宿主设置继承：

```yaml
voice:
  tts:
    provider: "local_engine"          # 这只宠物改用本地引擎念
    local:
      exe: 'D:\voice\sherpa-onnx-offline-tts.exe'
      model_dir: 'D:\voice\yuki-voice'
      speed: 1.15
  stt:
    provider: "openai_compatible"     # 这只宠物用云端识别
    http:
      api_url: "https://api.openai.com/v1/audio/transcriptions"
      api_key: "sk-..."               # 注意：写在这里的 Key 会随宠物目录一起分发
      model: "whisper-1"
```

| 字段 | 作用 |
| --- | --- |
| `voice.tts` | 覆盖合成设置：`provider`、`web_speech`、`http`、`local` 四段任写 |
| `voice.stt` | 覆盖识别设置：`provider`、`auto_send`、`web_speech`、`http`、`local` 任写 |

合并是**逐字段推导**的：只写 `provider: local_engine` 不会把 `args` 模板整段吃掉，
没写的键一律沿用宿主当前值。

生效时机：**每一句话都重新解析一次**，所以换宠物立刻换嗓子，改完 YAML 也不需要重启。

⚠️ 两点提醒：

- `voice` 里的 `http.api_key` 是**明文**，会跟着宠物目录一起被拷走。要分发给别人，
  别在里面写自己的 Key。
- 这只宠物自己的 `voice` 只管它自己；宿主 `settings.yaml` 里改的是所有宠物的默认值。

### hit_areas —— 可点击感应区

```yaml
hit_areas:
  - name: "head"
    label: "轻抚银发"       # 校准工坊里显示的名字
    rect:
      x: 64
      y: 4
      w: 192
      h: 122
    motion: "pat"            # 点中后播放的动作
    expression: "smile"      # 点中后的表情
    texts:                   # 随机取一条显示在气泡里
      - "唔……头发会乱掉的啦。不过，偶尔摸一下下也可以 ✨"
      - "大家看，发梢刚刚自己翘起来了——这个我没法解释。"
      - "银羽频道信号满格，随时待命 🎙️"
```

矩形坐标写在**与舞台等比的 320×340 坐标系**里，原点在 (160, 170)。详见下一节。

感应区可以有任意多个，也可以不写（不写就没有区域命中，但整只宠物仍然可通过轮廓点击）。

### drop_handlers —— 拖文件到宠物身上

```yaml
drop_handlers:
  - extensions: [".py", ".rs", ".ts", ".js", ".vue", ".json", ".yaml", ".yml", ".md", ".txt"]
    motion: "feed"
    expression: "smile"
    bubble_template: "🪶 银羽接住了 [{filename}]，正在读这段脚本……"
    action:
      type: "exec"
      command: "python"
      args: ["-c", "print('hello')"]
  - extensions: ["*"]      # 兜底，必须放最后
    motion: "feed"
    expression: "surprised"
    bubble_template: "已记下 [{filename}]"
    action:
      type: "emit"
      app_id: "broadcast"
      event: "pet.file_dropped"
      payload: {}
```

按 `extensions` 顺序匹配，第一个命中的生效，`"*"` 为通配。`bubble_template` 里的 `[{filename}]` 会被替换成实际文件名。

> **`exec` 的安全边界**：`type: "exec"` 会直接启动你写的命令。宿主不做白名单过滤，因此只写你自己信任的命令；想对外分发宠物包时优先用 `emit`。

### menus —— 星盘菜单

```yaml
menus:
  - id: "silverfeather_studio"
    label: "银羽直播间"        # 外圈主菜单的标题
    children:                  # 有 children 就展开成第二层面板
      - id: "silverfeather_greet"
        label: "向大家打招呼"
        badge: "HELLO"        # 可选，右上角小标签
        action:
          type: "emit"
          app_id: "internal"
          event: "pet.quick_action"
          payload:
            motion: "speaking"
            expression: "smile"
            text: "大家晚上好呀，我是银羽 🪶"
```

- `children` 为空或不写 → 默认手势（单击）直接执行 `action` 并关闭菜单。
- `children` 非空 → 默认手势只是展开子面板，不执行动作。
- 子项最多两层。

#### 菜单交互手感（`menu_interaction`）

上面那两条「默认手势」现在可以由配置改写。写在 `pet.yaml` 根上就是这只宠物整套菜单的手感，
写在某个菜单项里就只改那一项：

```yaml
menu_interaction:
  trigger: "double_click"     # 执行 action 的手势：click / double_click / long_press / hover
  expand: "click"             # 展开 children 的手势，同上
  long_press_ms: 500          # long_press 要按住多久（150–3000，默认 500）
  hover_intent_ms: 400        # hover 要在项上停多久（0–3000，默认 400）
  auto_expand_first: true     # 菜单弹出时自动展开第一个有 children 的项（默认 true）

menus:
  - id: "studio"
    label: "银羽直播间"
    interaction:              # 只覆盖这一项
      expand: "hover"
    children:
      - id: "greet"
        label: "打招呼"
        interaction: { trigger: "long_press" }   # 按住 0.5 秒才触发
        action: { type: "emit", app_id: "internal", event: "pet.quick_action" }
```

四条规则：

1. **两个手势互不干扰。** 一个项既可以有 `action` 也可以有 `children`，把 `trigger` 和
   `expand` 设成不同手势，两个功能就都可用（例：`expand: click` + `trigger: double_click`）。
2. **`trigger` 与 `expand` 撞在同一手势上时，展开优先，`action` 永远跑不到。** 宿主会在
   控制台打一行 `[menu_interaction] 菜单项 [id] 的 trigger 与 expand 都是 …`——这个错误在
   界面上看不出来，所以只在日志里说。
3. **没绑上该项的手势什么也不做**，不会退回「展开子菜单」（那正是以前只有单击可用的原因）。
4. **长按不会连带触发单击**：一次按住只算 `long_press`，松手那一下不会再当成 click。

`hover` 是唯一需要延时的：指针只是路过时不该触发，所以用 `hover_intent_ms` 要求「停留」。
想更灵敏就调小，0 表示一进入就触发。

配置缺哪一项就用默认，写了不认识的取值（比如 `trigger: "triple_click"`）会退回默认而**不是**
被带进渲染层——一个渲染层不认识的手势就是一个点不动的菜单项。越界的时间值会被夹到区间内。

> **`icon` 字段已不再渲染。** 界面统一使用文字按钮，因为 emoji 依赖系统字体、观感不可控，而且原先硬编码在 Vue 组件里、改一次就要动源码。写 `icon` 不会报错，但不会有任何显示效果。

全局默认可以写在 `config/global_menu.yaml` 根上的 `interaction:` 段（对所有宠物生效，
被宠物自己的 `menu_interaction` 覆盖，两者都是逐字段合并的）。

## 渲染类型与资源要求

| `type` | `entry` 指向 | 需要哪些文件 | 备注 |
| --- | --- | --- | --- |
| `sprite` | `.png` / `.jpg` / `.svg` | 单张图，或多张动作图 | 最通用，本仓库内置五只全是这种 |
| `live2d` | `model.model3.json` | Cubism SDK 的整套模型目录 | 动作名走 Cubism 的 Motion |
| `spine` | `skeleton.json` | Spine 运行时 + 贴图 + atlas | 动作名走 Spine animation |
| `vrm` | `*.vrm` | 单个 VRM 文件 | 动作名走 VRM 的 expression |

代码里四个适配器都实现了（`src/adapters/`），但仓库内**只有 sprite 有实际资产可参考**。非 sprite 类型请以对应格式的官方文档为准，并预期需要自行调试。

## 尺寸与坐标系（最容易踩的坑）

这一节是接入过程中唯一需要动手算的地方。搞错的表现是「角色被拉胖」或「点了没反应」。

### 绘制框：角色会被拉到固定的 280×298

宿主不按你的原图尺寸渲染，而是把你的图**强制拉伸到 280×298 的方框**（`src/adapters/SpriteAdapter.ts`）。所以：

> **你的图片长宽比必须等于 280 : 298 ≈ 0.9396，否则角色会被拉胖或压扁。**

反过来说，如果你的原图是 1024×1536（比例 0.667），直接放进去会被横向拉粗约 41%。正确做法是**自己把它放进一个 700×745 的画布里居中**（700 : 745 正好等于 280 : 298），两侧留透明边——这就是仓库里 `silverfeather_chibi` 三张图已经是 700×745 的原因。

宿主也接受 SVG：内置四只的 SVG 都写成 `viewBox="0 0 320 340"`，内部按比例适配，不会变形。

### 感应区坐标系：320×340，原点 (160, 170)

`hit_areas` 的 `rect` **不是**原图像素，而是与舞台等比的 320×340 坐标系，原点在中心 (160, 170)。

舞台实际是 360×420，映射关系为：

```text
localX = (x - 180 - offsetX) / scale + 160
localY = (y - 210 - offsetY) / scale + 170
```

反推（在 `scale: 1.0`、`offset: {x:0, y:0}` 时）就是加固定偏移：

```text
舞台坐标 = 感应区坐标 + (20, 40)
```

**怎么定 `rect` 的值**：先算出角色在 700×745 画布里实际占据的像素范围，再换算：

```text
hitX = canvasX / 700 × 320
hitY = canvasY / 745 × 340
```

量测一段的 alpha 内容边界可以用 Python：

```python
from PIL import Image
im = Image.open("pets/你的宠物/idle.png").convert("RGBA")
print(im.getchannel("A").getbbox())   # (x0, y0, x1, y1)，画布像素
```

再把上一步的 `rect` 叠到图上画框，肉眼确认框住的是你想要的位置——**目视校验一次比算三遍可靠**。

## 菜单可用的动作事件

菜单 `action.type: "emit"` 且 `app_id: "internal"` 时，`event` 只能取下面这些值。写错不会报错，但点击后没有任何反应：

| `event` | `payload` 可用字段 | 效果 |
| --- | --- | --- |
| `pet.quick_action` | `motion`、`expression`、`text` | 让宠物做一个动作并说话 |
| `pet.system_inspect` | — | 播报系统巡检（CPU / 内存 / 端口） |
| `pet.tactical_scan` | — | 全屏战术扫描 HUD |
| `pet.fortune_divination` | — | 抽一次运势 |
| `pet.feed_care` | `item`、`energy`、`affinity`、`xp` | 直接加好感/能量/经验 |
| `chat.toggle` | — | 开合内联对话舱 |
| `studio.toggle` | — | 开合蓝图校准工坊 |
| `pet.toggle_climb` | — | 吸附到前台窗口边缘 |
| `pet.edge_peek` | — | 从屏幕边缘探头 |
| `pomodoro.start` | `mode`、`minutes`、`label` | 开始番茄钟；`mode` 取 `focus` / `short_break` / `long_break` |
| `pomodoro.stop` | — | 停止番茄钟 |
| `pet.switch_model` | `pet_id` | 切换到另一只宠物 |

其他 `app_id`（如 `broadcast`）的事件会转发到 WebSocket 总线上连接的外部程序，由对方自己处理。

## 替换内置宠物

内置的五只同样只是「`pets/` 下的文件夹」，没有特殊待遇。三种改法：

**改文案 / 感应区 / 菜单** — 直接编辑 `pets/<id>/pet.yaml`，保存即热重载。

**换一只宠物的外观** — 把新图片按上面的命名放进同一个目录，改 `pet.yaml` 里的 `entry` 与 `animations`，`id` 保持不变（切换列表、已保存的偏好都靠它认人）。

**彻底换一只新宠物** — 新建文件夹，走上面「30 秒接入」。

另外，主机的偏好存在 `%APPDATA%\AI-Pets\`，里面有 `active_pet_id`。删掉这个字段或让它指向不存在的 ID，宿主会回落到内置默认宠物。

## 常见问题

**宠物没出现在切换列表里**
按顺序排查：文件夹名与 `id` 是否一致、ID 是否只含 `a-z A-Z 0-9 _ -`、`pet.yaml` 是不是真的存在且能解析。宿主会跳过不合格的目录且**不打印错误**，这是设计上为了不让一只坏宠物拖垮整个列表。想自查，用项目自带的加载器跑一遍：

```bash
npm test -- tests/silverfeatherPet.spec.ts
```

**角色看起来太胖 / 太扁**
图片长宽比不是 0.9396，见[尺寸与坐标系](#尺寸与坐标系最容易踩的坑)。

**点了感应区没反应**
`rect` 坐标算错了。记住 `scale: 1.0` 时舞台坐标 = 感应区坐标 + (20, 40)。

**主题没生效，配色还是默认蓝**
检查 `theme:` 是不是顶格写在 `pet.yaml` 里（不要缩进到 `model:` 或其他块下面），以及每个颜色值是不是带引号的字符串。RGB 用 `#RRGGBB`，`rgba()` 的 alpha 不能写成 `1`。

**菜单项点了没反应**
`event` 名字不在[上表](#菜单可用的动作事件)里。用 `app_id: "internal"` 时只认那 12 个。

**改了没生效**
`pets/` 的监听有 300ms 去抖，正常保存即生效。如果改的是资源图片，确认文件名与 `pet.yaml` 里写的一致（**大小写敏感**）。

**外部程序切不到我新加的宠物**
`switch_pet` **已经不限于内置宠物**：只要 `pets/<id>/` 目录存在就能切。
切不过去有两类原因，回绝原文不同：
① id 不合法——只能是字母、数字、`_` `-`，不超过 64 字符
（字母不限 ASCII，中文目录名可以），带路径分隔符、`.`、`..` 或控制字符的会被拒；
② id 合法但 `pets/<id>/pet.yaml` 不在宿主解析到的 `pets/` 下——回绝里会**写出宿主实际搜索的那个绝对路径**，
拿它和你放文件的位置对一下就能看出问题（常见是放到了仓库根的隔壁、或便携版旁边的 `pets/`）。
注意判据是 `<id>/pet.yaml` 这个**文件**：只建了空目录、还没放清单的宠物，外部切换一样会被拒。
两类回绝原文见[使用说明书](使用说明书.md)的 12.3 节。

## 一份最小可用的 pet.yaml

```yaml
id: "my_pet"
name: "我的宠物"
version: "1.0.0"
type: "sprite"
description: "示例"

model:
  entry: "idle.png"
  scale: 1.0
  offset: { x: 0, y: 0 }
  fps: 60
  animations:
    idle:
      file: "idle.png"
      loop: true

expressions:
  neutral:
    tint: 0xffffff

theme:
  primary: "#38bdf8"
  accent: "#f43f5e"

persona:
  identity: "你是小星。"
  traits: ["活泼", "好奇"]
  style_notes: "回复不超过 30 字。"

hit_areas:
  - name: "head"
    label: "摸摸头"
    rect: { x: 85, y: 45, w: 150, h: 110 }
    motion: "pat"
    expression: "smile"
    texts:
      - "你好呀！"

menus:
  - id: "main"
    label: "主菜单"
    children:
      - id: "greet"
        label: "打招呼"
        action:
          type: "emit"
          app_id: "internal"
          event: "pet.quick_action"
          payload:
            motion: "happy"
            expression: "smile"
            text: "你好！"
```

## 扩展点全表

「不改源码就能改的东西」一览。**每一条都可以只用配置文件表达**；需要动源码的那些单列在
下面的表里，并写清要改几个文件。

### 只写配置就能扩展

| 想改什么 | 写在哪 | 字段 |
| --- | --- | --- |
| 外观（配色） | `pets/<id>/pet.yaml` | `theme` |
| 模型与动作 | 同上 | `model`（`entry` / `scale` / `offset` / `fps` / `animations`） |
| 表情着色 | 同上 | `expressions` |
| 性格（喂给大模型） | 同上 | `persona` |
| 音色（覆盖 `settings.yaml`） | 同上 | `voice` |
| 可点击感应区 | 同上 | `hit_areas` |
| 拖入文件的反应 | 同上 | `drop_handlers` |
| 菜单结构与动作 | 同上 | `menus`（`children` / `action` / `badge`） |
| 菜单手势（单击/双击/长按/悬停） | 同上 | `menu_interaction`（根级默认）与每个菜单项的 `interaction` |
| 全局菜单项（对所有宠物生效） | `config/global_menu.yaml` | `menus`、`interaction` |
| 语音合成 / 识别方式与参数 | `config/settings.yaml` | `audio.tts.*`、`audio.stt.*` |
| 对话的记忆轮数与流式 | 伴生舱「网页与AI脑桥」界面（存 `localStorage`） | `historyTurns`、`stream` |
| 面板内容（控件树） | 外部程序发 `panel.open`，或 `window.PetBridge.panel.open()` | `schema.widgets` |
| 面板控件做什么 | 同上，控件自己的 | `effect` |
| 面板控件外观/布局 | 同上 | `container` + `children` + `layout` |
| 屏幕标注 | 外部程序发 `hud.draw` | `annotations` |
| 外部程序可请求的宿主动作 | 外部程序发 `safe_action` | 8 个 `action_id`（见使用说明书 12.3） |

### 需要改源码的（附改动量）

| 想加什么 | 要改的文件 | 说明 |
| --- | --- | --- |
| **一种新的面板控件** | `src/types/pet.d.ts`（联合类型）+ `src/companion/SduiWidgetView.vue`（一个渲染分支） | **两个文件**。副作用不用动（由 `effect` 声明式解析），面板回读初值也不用动（按 `effect.setting` 找，不认 id）。改完 `npm run typecheck` 会把漏掉的分支报出来 |

| **一种新的菜单手势** | `src/types/pet.d.ts`（`MenuGesture`）+ `src/utils/menuInteraction.ts`（`planMenuGesture`）+ `src/components/RadialMenu.vue`（绑定事件） | 三个文件 |

### 加一种新控件：照抄的步骤

以加一个 `rating`（五星评分）控件为例。要改的就是上表说的两个文件。

**第 1 步，`src/types/pet.d.ts` 的 `SduiWidget` 里加一个成员：**

```ts
  | {
      id: string;
      type: 'rating';
      label: string;
      /** 0~5，允许半星。 */
      value: number;
      max?: number;
      effect?: SduiEffect;
    };
```

**第 2 步，`src/companion/SduiWidgetView.vue` 的模板里加一个分支**（放在
`log_viewer` 之前、最后的 `v-else` 之前），并在 `<script setup>` 里加一个处理函数：

```vue
  <div v-else-if="widget.type === 'rating'" class="pod-col">
    <span class="pod-label">{{ widget.label }}</span>
    <div class="rating-row">
      <button
        v-for="star in widget.max || 5"
        :key="star"
        class="rating-star"
        :class="{ on: star <= widget.value }"
        @click="handleRatingChange(widget, star)"
      >★</button>
    </div>
  </div>
```

```ts
async function handleRatingChange(
  widget: Extract<SduiWidget, { type: 'rating' }>,
  star: number
): Promise<void> {
  widget.value = star;
  // 和别的控件走同一个提交口：先日志、再本地副作用、最后回发外部 app。
  await commitWidget(widget.effect, widget.id, widget.value, `评分 ${widget.label}`);
}
```

**第 3 步，验证：**

```bash
npm run typecheck   # 漏了模板分支或漏了 union 成员都会在这里报错
npm test            # tests/sduiWidgets.spec.ts 会渲染每一种控件，新成员自动被覆盖
```

不需要改的地方（这是重点）：外部 app 的接口、`effect` 的解析、面板初值的回读、
事件回发的代码——**都不用动**。

### 加一种新交互：照抄的步骤

以加一个 `right_click` 手势为例。

**第 1 步，`src/types/pet.d.ts`：**

```ts
export type MenuGesture = 'click' | 'double_click' | 'long_press' | 'hover' | 'right_click';
```

**第 2 步，`src/utils/menuInteraction.ts` 的 `GESTURES` 数组里加上 `'right_click'`。**
这一步不做的话，`normalizeMenuInteraction` 会把它当成不认识的值而退回默认——**这正是设计
意图**：一个渲染层不认的手势不该被带进去，那样会得到一个点不动的菜单项。

**第 3 步，`src/components/RadialMenu.vue` 里绑定事件：**

```vue
@contextmenu.prevent.stop="handleNodeGesture(item, 'right_click')"
```

（主菜单节点与子面板按钮两处都要加，否则这个手势只在一层可用。）

**第 4 步，验证：** `npm run typecheck && npm test`。`tests/menuInteraction.spec.ts` 里那条
"accepts each gesture on either job" 用的就是 `GESTURES`，新增取值会自动被覆盖；
再补一条「同一个手势绑定到 trigger 和 expand 会告警」的用例。
