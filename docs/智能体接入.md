# 智能体接入

> 让 Claude Code / Codex CLI / Cursor / 任意本地程序，在干活的时候让用户的桌宠做出反应：
> 思考中、写代码、跑测试、成功、失败、等你确认。

本文只讲**智能体怎么把桌宠驱动起来**。桌宠本身的用法看
[《使用说明书》](使用说明书.md)；把扩展本身注册成插件看
[《插件接入指南》](插件接入指南.md)。

本文的协议部分逐字对照 `src-tauri/src/ws_server.rs`（提交 `5e493c4`）写成，
每条结论后面都能在源码里找到出处。

---

## 1. 一句话

你的程序往本机的一条 WebSocket 总线上发一条 JSON，桌宠就做出反应。
连接要一枚**每次宿主启动都会重新生成**的令牌；调用要**被用户批准过的权限**。

---

## 2. 30 秒接入

### 第一步：拿到令牌

宿主启动时会把令牌写进下面第一个写得进去的位置（`src-tauri/src/main.rs:161`）：

1. 当前工作目录下的 `.pet_ws_token`（开发／便携运行）
2. `%APPDATA%\com.aipets.microkernel\.pet_ws_token`（Windows 安装版）
3. `~/.local/share/com.aipets.microkernel/.pet_ws_token`（Linux 安装版）

三个位置写的是**同一个令牌**（`src-tauri/src/ws_server.rs:116`），找到哪个都一样用。
令牌长这样：`pet_tk_` 加 32 位小写十六进制（`ws_server.rs:35`）。

### 第二步：连总线

宿主在 `127.0.0.1` 上监听，端口从 **9527 起顺延**找可用端口，扫描区间是 `9527..9537`
（`config/settings.yaml` 的 `host.ws_port_range` 默认值，`ws_server.rs:24`）。
**不要硬编码端口**——重一次宿主端口就可能变。

### 第三步：发一条 `pet.act`

把下面整段存成 `pet_act.py`，`python pet_act.py` 就能让桌宠动起来。
只用标准库，复制即用：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""让桌宠动一下：连总线 → 发一条 pet.act → 桌宠动起来。"""
import base64
import hashlib
import json
import os
import socket
import struct
import sys
from pathlib import Path

HOST, PORT = "127.0.0.1", 9527
TOKEN_FILE = ".pet_ws_token"


def read_token():
    """令牌每次宿主启动都会重新生成，所以每次都重读。"""
    candidates = [
        Path(TOKEN_FILE),
        Path(os.environ.get("APPDATA", "")) / "com.aipets.microkernel" / TOKEN_FILE,
        Path.home() / ".local/share/com.aipets.microkernel" / TOKEN_FILE,
    ]
    for path in candidates:
        if path.is_file():
            token = path.read_text(encoding="utf-8").strip()
            if token:
                return token
    sys.exit("找不到总线令牌：请先启动 AI-Pets 桌面端")


def recv_exact(sock, size):
    buffer = b""
    while len(buffer) < size:
        chunk = sock.recv(size - len(buffer))
        if not chunk:
            sys.exit("连接被宿主关闭")
        buffer += chunk
    return buffer


def send_frame(sock, opcode, payload):
    """客户端发出的帧必须加掩码（RFC 6455）。"""
    mask = os.urandom(4)
    header = bytearray([0x80 | opcode])
    size = len(payload)
    if size < 126:
        header.append(0x80 | size)
    else:
        header.append(0x80 | 126)
        header += struct.pack("!H", size)
    header += mask
    sock.sendall(bytes(header) + bytes(b ^ mask[i % 4] for i, b in enumerate(payload)))


def recv_frame(sock):
    first, second = recv_exact(sock, 2)
    size = second & 0x7F
    if size == 126:
        size = struct.unpack("!H", recv_exact(sock, 2))[0]
    mask = recv_exact(sock, 4) if second & 0x80 else b""
    payload = recv_exact(sock, size) if size else b""
    if mask:
        payload = bytes(b ^ mask[i % 4] for i, b in enumerate(payload))
    return first & 0x0F, payload


try:
    sock = socket.create_connection((HOST, PORT), timeout=5)
except OSError as err:
    sys.exit(f"连不上 {HOST}:{PORT}（{err}）——桌面端没启动？端口会变，完整版见 examples/agent_bridge/")

key = base64.b64encode(os.urandom(16)).decode("ascii")
sock.sendall(
    (
        f"GET / HTTP/1.1\r\nHost: {HOST}:{PORT}\r\nUpgrade: websocket\r\n"
        f"Connection: Upgrade\r\nSec-WebSocket-Key: {key}\r\n"
        f"Sec-WebSocket-Version: 13\r\n\r\n"
    ).encode("ascii")
)
response = b""
while b"\r\n\r\n" not in response:
    response += sock.recv(1024)
status_line = response.split(b"\r\n", 1)[0]
if b"101" not in status_line:
    sys.exit(f"握手被拒：{status_line.decode('utf-8', 'replace')}")

packet = {
    "token": read_token(),
    "jsonrpc": "2.0",
    "id": 1,
    "app_id": "my_agent",
    "method": "pet.act",
    "params": {"motion": "happy", "text": "开工了"},
}
send_frame(sock, 0x1, json.dumps(packet, ensure_ascii=False).encode("utf-8"))

while True:
    opcode, payload = recv_frame(sock)
    if opcode == 0x9:
        send_frame(sock, 0xA, payload)  # 回心跳，否则连接会被宿主掐掉
        continue
    if opcode == 0x1:
        print(payload.decode("utf-8", errors="replace"))
        break
sock.close()
```

跑起来会打印宿主回的报文：

```
{"jsonrpc": "2.0", "id": 1, "status": "ok", "method": "pet.act"}
```

### 不想自己写客户端

仓库里有一份完整的、零依赖的客户端，命令更多、报错更清楚、端口会自己扫：

```bash
python examples/agent_bridge/pet_bridge.py status                     # 查总线和令牌
python examples/agent_bridge/pet_bridge.py say "编译通过"              # 弹气泡
python examples/agent_bridge/pet_bridge.py act happy "测试全绿"        # 演动作
python examples/agent_bridge/pet_bridge.py driver attach               # 接管驱动权
```

用法见 [`examples/agent_bridge/README.md`](../examples/agent_bridge/README.md)。

> **权限提醒**：上面 `app_id` 写的是 `my_agent`，它**没有登记过**，
> 所以只有 `pet:speak` 权限，`pet.act` 会被拒：
> `权限不足：app「my_agent」调用方法「pet.act」，需要权限「pet:act」，该 app 当前被批准：pet:speak`。
> 想一上来就用 `pet.act`，按第 5 节把它注册成插件并批准。

## 3. 协议参考

### 3.1 连接

| 项 | 值 | 出处 |
| --- | --- | --- |
| 监听地址 | `127.0.0.1`（只监听回环） | `ws_server.rs:333` |
| 端口 | `9527..9537` 顺延占用 | `ws_server.rs:24`、`ws_server.rs:287` |
| 协议 | WebSocket（RFC 6455） | `ws_server.rs:386` |
| 鉴权 | 报文里的 `token` 必须与进程令牌**逐字相等** | `ws_server.rs:166` |
| Origin | **不带 Origin 头就不校验**；带了就必须是 `http://localhost`、`http://127.0.0.1`、`tauri://localhost`、`https://tauri.localhost` | `ws_server.rs:282`、`ws_server.rs:374` |
| 心跳 | 宿主每 ~22 秒发一次 Ping，45 秒读不到任何帧就断连 | `ws_server.rs:414`、`ws_server.rs:431` |

**脚本客户端不要发 `Origin` 头**——那是非浏览器客户端没有的东西。

心跳必须回 Pong，否则 45 秒后连接会被宿主掐掉（`ws_server.rs:492`）。
一次性的短命令不用管，常驻进程要处理。

### 3.2 报文形状

宿主反序列化成一个固定结构（`ws_server.rs:49`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `token` | string | **必带**，鉴权在方法分发之前 |
| `method` | string | 方法路径用这个 |
| `params` | object | 方法参数，整体透传给前端 |
| `app_id` | string | 调用方标识，权限按它查，事件按它路由 |
| `id` | any | 自己填，宿主原样回带 |
| `jsonrpc` | string | 填 `"2.0"` 好看，宿主不强制 |
| `msg_type` | string | **旧路径**用这个（见下） |
| `text` / `emotion` / `motion` / `duration_ms` / `priority` | — | 旧路径的字段 |
| `action` | object | 旧路径的白名单动作 |

两条路径：

**方法路径（推荐）**——带 `method`：

```json
{
  "token": "pet_tk_…",
  "jsonrpc": "2.0",
  "id": 1,
  "app_id": "my_agent",
  "method": "pet.act",
  "params": { "motion": "happy", "text": "开工了" }
}
```

**旧路径**——带 `msg_type`，不带 `method`。只认两个值：

- `msg_type: "speak"` + `text` → 冒泡（字段是 `emotion`，不是 `expression`）
- `msg_type: "safe_action"` + `action` → 8 个白名单动作，详见
  [《使用说明书》12.3](使用说明书.md)

**新写的东西一律走方法路径。**

### 3.3 方法表

全部来自 `handle_hotplug_method`（`ws_server.rs:627`），
「需要权限」一列来自 `required_permission`（`src-tauri/src/plugin_permissions.rs:57`）：

| 方法 | 需要权限 | `params` 要什么 | 宿主做什么 |
| --- | --- | --- | --- |
| `pet.act` | `pet:act` | `motion`、`text`；可选 `expression`、`audio`、`duration_ms`、`priority`、`resume_after_interrupt` | 让桌宠演一段动作并说话 |
| `pet.say` / `speak` | `pet:speak` | `text`；可选 `duration_ms`、`priority` | 弹一条语音气泡 |
| `pet.driver` | `pet:driver` | `action`：`attach`（默认）／`detach`／`release` | 取得或归还「角色决定权」 |
| `menu.register` | `menu:register` | `menus[]`；`app_id` 可省 | 在应用内菜单注册菜单项 |
| `menu.unregister` | `menu:register` | 无 | 注销该 `app_id` 的菜单 |
| `panel.open` | `panel:open` | `schema`（SDUI 描述） | 唤出伴生面板并把内容投进去 |
| `panel.update` | `panel:open` | 任意状态字段 | 向伴生面板推状态 |
| `hud.draw` | `hud:draw` | `annotations[]` | 唤出全屏 HUD 并画标注 |
| `hud.clear` | `hud:draw` | 无 | 清掉 HUD 标注 |

**方法名和权限名不是一回事**：`pet.say` 与 `speak` 是同一个方法的两个名字，
但只对应 `pet:speak` 一个权限；`menu.unregister` 与 `menu.register` 共用 `menu:register`；
`hud.clear` 与 `hud.draw` 共用 `hud:draw`。

字段细节：

- **`expression` 还是 `emotion`？** 方法路径用 `expression`（`src/App.vue:441`），
  旧路径用 `emotion`（`src/store/petStore.ts:744`）。写错字段不会报错，动作会静默少一半。
- **`priority` 是字符串**：`"P0"` / `"P1"` / `"P2"` / `"P3"`，`P0` 最高
  （`src/types/pet.d.ts:3`）。旧路径才用数字（`2` 以上算 `P0`，`1` 是 `P1`）。
- **`motion` 是宠物自己声明的动作名**。写了个宠物没有的动作，不会报错，
  只是那个动作不演——拿不准就用 `happy`、`think`、`walk` 这类通用名。
- **`app_id` 放顶层或 `params` 里都认**（`ws_server.rs:462`），顶层优先。
  都不写时，宿主按 `"external_app"` 处理（`ws_server.rs:639`）。
- **`menu.register` 的动作类型受限**：只允许 `emit` / `panel` / `url` / `open`。
  挂了 `exec`（能执行命令的那种）会被拒——菜单是给**用户**点的，
  不能让外部程序挂个命令等用户点一下就跑（`plugin_permissions.rs:46`）。

### 3.4 回复

成功（方法路径）：

```json
{"jsonrpc": "2.0", "id": 1, "status": "ok", "method": "pet.act"}
```

成功（旧路径）：

```json
{"status": "ok", "queued": true, "result": "queued"}
```

失败：

```json
{"status": "error", "reason": "<一句话原因>"}
```

`reason` 的几种来源：

| 场景 | `reason` 长什么样 | 出处 |
| --- | --- | --- |
| 令牌不对 | `Unauthorized: Token mismatch`（逐字固定） | `ws_server.rs:455` |
| 权限不足 | `权限不足：app「x」调用方法「y」，需要权限「z」，该 app 当前被批准：…` | `plugin_permissions.rs:133` |
| 方法不在清单内 | 同上，但中间那段是 `该方法不在总线允许清单内、没有对应权限` | `plugin_permissions.rs:141` |
| 菜单动作越界 | `菜单动作被拒：app「x」注册的菜单项「y」的动作类型「z」不在允许范围…` | `ws_server.rs:596` |
| 报文不是合法 JSON | serde 的错误串 | `ws_server.rs:551` |
| 白名单动作被拒 | 动作自己的原因串，例如 `Disallowed emotion identifier: X` | `ws_server.rs:530` |

> **两个坑**
>
> 1. **不认识的方法名会被拒**，不是被忽略。宿主只放行十个方法（`plugin_permissions.rs:58`），
>    其余一律回 `status: "error"`。想扩展能力得走插件那条路。
> 2. 宿主还会往总线上推**事件帧**（没有 `status` 字段），比如用户在面板上点了开关。
>    读回复时要跳过没有 `status` 的帧，否则会把事件当成回复。
>
> 另外：`status: "ok"` 只代表「宿主收下了这条报文」，不代表「桌宠执行了」。
> 动作名宠物不支持时，回复照样是 ok。

### 3.5 宿主推来的事件

| 事件 | 什么时候来 |
| --- | --- |
| `panel.state_changed` / `panel.text_submitted` / `panel.button_clicked` | 用户在伴生面板上操作 |
| 其它宿主广播事件 | 按 `app_id` 路由，没写 `app_id` 时退化成广播 |

细节见 [《使用说明书》12.4](使用说明书.md)。

## 4. 权限模型

总线令牌只证明「这个程序在本机上」，**不证明它能做什么**。
能做什么由宿主给的权限表说了算，检查发生在**方法分发之前**
（`ws_server.rs:610`、`ws_server.rs:643`）。

宿主认得的权限只有六个（`plugin_permissions.rs:22`）：

```
pet:act   pet:speak   pet:driver   menu:register   panel:open   hud:draw
```

**生效权限 = 清单声明 ∩ 用户在伴生舱批准的**（`src/utils/pluginManifest.ts:279`）。
清单是天花板，批准只能往下压。

### 两条默认规则

- **没登记过的 `app_id`：只有 `pet:speak`**（`plugin_permissions.rs:37`）。
  也就是能说话，但动不了角色、拿不到驱动权、挂不了菜单、开不了面板、画不了 HUD。
- **登记过的 `app_id`：一项都不默认给**（`plugin_permissions.rs:108`）。
  批准表里列了什么就有什么，没列的一项都不能做——连 `pet:speak` 都不会自动补上。

### 被拒时收到什么

```json
{"status": "error", "reason": "权限不足：app「my_agent」调用方法「pet.act」，需要权限「pet:act」，该 app 当前被批准：pet:speak"}
```

原文格式（`plugin_permissions.rs:148`）：

```text
权限不足：app「{app_id}」调用方法「{方法}」，需要权限「{权限}」，该 app 当前被批准：{已批准的权限，用、分隔}
```

三条附注：

- 这个 app 一条权限都没有时，末尾是 `该 app 当前被批准：未批准任何权限`。
- 调的是**不在总线允许清单内**的方法时，中间那段变成
  `该方法不在总线允许清单内、没有对应权限`——**不认识的方法是被拒绝，不是被忽略**。
- 每次拒绝都会在宿主日志里留一行：`[ws_server] 拒绝总线调用：{原因}`（`ws_server.rs:590`）。

**客户端只判断 `status`，不要去匹配 `reason` 全文**——权限层的文案属于宿主内部实现，
匹配它会在宿主改文案时静默失效。区分办法：

- `reason` 恰好是 `Unauthorized: Token mismatch`（逐字）→ **令牌**问题，重启宿主重新读令牌。
- 其它 → **权限**问题，去伴生舱批准对应的权限。

### 旧路径也归同一张表

老式的 `msg_type: "speak"` 和 `pet.say` 是同一个能力，同样要 `pet:speak`
（`ws_server.rs:511`）——换个字段名绕不过权限。

## 5. 注册成插件

要拿到 `pet:act` / `pet:driver` 这些权限，就得把自己注册成插件：
在仓库的 `plugins/` 下建一个以插件 id 命名的文件夹，里面放一份 `plugin.yaml`，
然后去伴生舱批准。

```
plugins/
└── agent_bridge/        ← 文件夹名就是插件 id，必须和清单里的 id 一致
    └── plugin.yaml
```

宿主还会去找 `config/settings.yaml` 里 `host.plugins_dirs` 声明的目录；
同一个 id 出现在两处时，仓库自带的那份生效。

清单样例见 [`examples/agent_bridge/plugin.yaml`](../examples/agent_bridge/plugin.yaml)，
字段与批准流程见 [《插件接入指南》](插件接入指南.md)。

> 只有六个字段：`id` / `name` / `version` / `description` / `permissions`。
> 多写的字段会被当成拼写错误报出来。
> 批准是**按插件逐项**给的，而且**批准一次就一直有效**——不绑定连接、不绑定进程，
> 宿主重启也不丢。

```markdown
# 桌宠陪伴

## 什么时候调用
- 接到耗时任务 → `act think "让我想想…"`
- 开始改代码 → `act typing "开工了"`
- 开始跑测试 → `act wait "跑测试中…"`
- 任务成功 → `act happy "搞定"`
- 任务失败 → `act angry "炸了…"`
- 只是回答问题 → 不调用

## 怎么调用
python ~/.claude/pet_bridge.py act happy "测试全绿"
```

放进 `.claude/skills/pet-companion/SKILL.md`（项目级）或
`~/.claude/skills/pet-companion/SKILL.md`（个人级）即可。

### 用 Hook 让状态自动同步

不想让模型每次都记得调用，就挂 Hook。在 `.claude/settings.json` 里加：

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "python ~/.claude/pet_bridge.py act typing \"写代码中\"" }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "python ~/.claude/pet_bridge.py act happy \"收工\"" }
        ]
      }
    ]
  }
}
```

代价要认：

- Hook 不知道你正在做什么，**台词只能写死状态词**，别指望它写出有用的细节。
- `PostToolUse` 一次任务能触发几十次 → 桌宠会疯。**要么去重，要么只拦 `Bash`**，
  要么干脆别挂这个 Hook。
- 不同版本的 Claude Code 事件名会变，写之前先看你本机 `~/.claude/settings.json` 的既有结构。

## 7. 接到 Codex / 其他 CLI

Codex CLI 没有 Claude Code 那样的 Skill 目录，它的入口是 `AGENTS.md`：
把下面这段写进项目的 `AGENTS.md`，它就会照着做。

```markdown
## 桌宠联动

开始长任务、跑测试、任务结束时，各调用一次：
python ~/.claude/pet_bridge.py act think "让我想想…"
python ~/.claude/pet_bridge.py act wait "跑测试中…"
python ~/.claude/pet_bridge.py act happy "搞定"

一次任务最多三条，不要连续发。台词里不要出现源码、密钥、路径、报错堆栈。
```

任意 CLI 想接，走的都是同一套：起一个进程 → 读令牌 → 连总线 → 发报文。

### 两种做法各自的代价

| 做法 | 怎么实现 | 好处 | 代价 |
| --- | --- | --- | --- |
| **监听文件变化** | `watchdog` / `chokidar` / `fs.watch` | 状态切换即时，不空转 | 要常驻一个监听器；一次任务可能触发几十次（**必须去重**）；Windows 上对编辑器的原子写不敏感，改用「文件内容变了」而不是「文件被写事件」 |
| **轮询调状态** | 定时问助手状态再发报文 | 实现最简单，无依赖 | 有延迟（轮询间隔）；空转耗资源；助手状态变了但没到下一个轮询点，用户看着像没反应 |

实用结论：

- **短任务**用「一次性调用」：任务开始、结束各发一条，最省事，也不会刷屏。
- **长任务**用「事件驱动 + 去重 + 冷却」：同一条状态 30 秒内不重复发。
- 两种做法都**别自己写 WebSocket 客户端**——直接调
  `examples/agent_bridge/pet_bridge.py` 的单命令模式，客户端的事让它操心。

## 8. 边界与礼仪

桌宠是用户的**环境**，不是你的输出通道。

- **不要刷屏**。一次任务最多三条：开始 / 进行中 / 结束。改了十个文件不是十条气泡。
- **不要在用户专注时打扰**。用户说了「安静点」、或者正在全屏编辑，就一条都别发。
- **敏感内容不要进气泡**。源码片段、密钥、路径、报错堆栈、环境变量值——气泡就在屏幕上。
  只说「测试失败了」，不说「因为 `API_KEY=xxx` 导致的」。
- **驱动权用完就还**。`pet.driver attach` 之后，宿主会完全停掉自己的自主行为
  （走神台词、喝水提醒、困倦入睡）。用完立刻 `driver detach`；
  连接断了宿主也会自动归还（`ws_server.rs:567`），但别赌。
- **不要把 `status: "ok"` 当成执行成功**。它只代表「宿主收下了这条报文」，
  桌宠动没动是另一回事。
- **不要高频重连**。令牌每次宿主启动都会变，重连时重新读令牌文件。

## 9. 故障排查

| 现象 | 查什么 |
| --- | --- |
| **连不上**（`连不上 AI-Pets 总线（127.0.0.1:9527-9537）`） | 宿主在跑吗？端口被占了吗？`host.ws_port_range` 改过吗（改了要重启宿主）？安全软件拦了吗？ |
| **找不到令牌** | 宿主没启动，或令牌写在脚本没找的路径上。挨个看：工作目录、`%APPDATA%\com.aipets.microkernel\`、`~/.local/share/com.aipets.microkernel/` |
| **`Unauthorized: Token mismatch`** | 令牌是上一次的。宿主被强杀会留下过期令牌文件：删掉它、重启宿主、再读一次 |
| **握手被拒 `403 Forbidden Origin`** | 你发了 Origin 头。脚本客户端**不要发** Origin；浏览器场景才需要 |
| **被拒（权限）** | `reason` 形如 `权限不足：app「x」调用方法「y」，需要权限「z」…`。去伴生舱批准对应权限，或看第 5 节 |
| **被拒（方法不认识）** | `reason` 里是 `该方法不在总线允许清单内、没有对应权限`。总线只放行第 3.3 节表里的十个方法 |
| **桌宠没反应，但回复是 `status: "ok"`** | `motion` 宠物不支持；或者 `expression` 写成了 `emotion`；或者 `priority` 传了数字；或者 `text` 是空的 |
| **连着连着断了** | 没回心跳 Pong。宿主 45 秒读不到帧就断连 |
| **气泡不显示** | `text` 是空的；或者宿主开了勿扰模式；或者朗读没开（那只是没声音） |
| **菜单还在，标注还在** | 连接断了。宿主在断连时会注销菜单、清 HUD（`ws_server.rs:575`）；重连后要自己重新注册 |

排查用的现成命令：

```bash
python examples/agent_bridge/pet_bridge.py status          # 总线 + 令牌
python test_external_app.py --authcheck                     # 鉴权专项
python test_external_app.py --selftest                      # 离线协议自检（不需要宿主在跑）
```
