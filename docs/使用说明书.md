## 1. 这是什么

AI-Pets 是一个常驻 Windows 桌面的宠物宿主。桌面上有一只可互动的虚拟宠物，
它会自己游荡、攀爬窗口、贴边探头、在长时间没人理它之后进入低功耗休眠；
同时提供一个伴生控制面板和一个全屏标注层，供外部程序把菜单、面板内容和屏幕标注投递进来。

- 产品名 `AI-Pets`，版本 `2.0.1`，应用标识 `com.aipets.microkernel`
- 运行平台 Windows，依赖 WebView2 Runtime

### 三个窗口

| 窗口 | 标题 | 大小 | 启动时可见 | 作用 |
| --- | --- | --- | --- | --- |
| `main` | `AI-Pets` | 360×420 | 是 | 桌宠主舞台 |
| `companion` | `AI-Pets Companion` | 380×520 | 否 | 伴生控制中心 |
| `hud` | `AI-Pets Tactical HUD` | 铺满当前显示器 | 否 | 全屏 AR 标注层（恒为鼠标穿透） |

三个窗口都是无边框、始终置顶、不进任务栏、不参与 Alt+Tab 的透明窗口。

## 2. 安装

### 2.0 最省事：从 Releases 下载

不想折腾本机环境，直接去
[Releases 页面](https://github.com/ZiZiZiNone/AI-Pets/releases) 下载最新版本的
`AI-Pets_*_x64-setup.exe`，双击安装即可，**不需要管理员权限**。

这些安装包是由 GitHub Actions 在预装 MSVC Build Tools 的 windows runner 上构建的，
等同于官方标准构建。要自己从源码构建，见 `README.md` 的「从零启动」。

### 2.1 两个安装包

打包会同时产出两个安装器，文件名固定：

```text
src-tauri/target/release/bundle/
├── msi/AI-Pets_2.0.1_x64_en-US.msi      体积随图标变化，以实际打包为准
└── nsis/AI-Pets_2.0.1_x64-setup.exe    同上
```

### 2.2 选哪个

**普通用户请用 NSIS 包（`AI-Pets_2.0.1_x64-setup.exe`）。**

- NSIS 按当前用户安装到 `%LOCALAPPDATA%`，**不需要管理员权限**。
- MSI 由 Tauri 的 WiX 打包器固定生成 per-machine 包，**安装时需要提权**。
  用管理员命令行安装时 `msiexec /i ... /qn` 返回 `1603` 或 `Error 1925` 属预期现象，不是安装包损坏。
  当前 Tauri 版本的 `WixConfig` 未暴露 `installMode`，因此这个差异**不是可配置项**。

### 2.3 卸载

程序没有自定义安装脚本，卸载走 Windows「已安装的应用」→ 找到 AI-Pets → 卸载。

### 2.4 安装后文件在哪

宿主按以下顺序找配置目录，取第一个存在的：

1. 当前工作目录下的 `config`
2. 上级目录的 `config`（从源码目录启动时的布局）
3. 可执行文件同级的 `config`（便携版）
4. 可执行文件同级的 **`_up_\config`**（安装后的实际位置）

第 4 条是安装版的真实位置：打包器把资源路径里的 `../` 编码成了一个名为 `_up_` 的目录。
**所以安装后不要去 exe 同级找 `config\`，要找 `_up_\config\`。** `pets\` 同理。

## 3. 首次启动

### 3.1 会自动发生的事

1. 桌宠出现在**当前显示器的右下角**（右边距 48、下边距 72 像素，按显示器缩放换算），而不是配置里写的坐标。
2. 桌宠打招呼，弹出激活提示（见 4.3）。
3. 宿主生成一枚总线令牌并写入 `.pet_ws_token`。
4. 托盘图标出现，提示文字 `AI-Pets — 全息微内核桌面伴侣`。
5. 本地 WebSocket 总线在 `127.0.0.1` 上从 9527 起顺延找可用端口。
6. `config/` 与 `pets/` 两个目录被监听，之后改配置会热重载。

### 3.2 令牌文件在哪

令牌形如 `pet_tk_` 加 32 位十六进制字符，由操作系统随机源派生，不含进程号。
**每一处可写位置都会写一份**（内容相同，随进程一起失效、随退出一起删除）：

1. 宿主进程的工作目录；
2. `%APPDATA%\com.aipets.microkernel\.pet_ws_token`。

写多份而不是只写第一份，是为了让**从别的目录启动的客户端**也能找到这条总线——两个共享同一套
宠物包的项目按定义就不在同一个目录里，只认工作目录等于要求使用者手工配一个路径。

第一处通常是 per-machine 的 `C:\Program Files`，普通用户无法在里面建文件，所以**安装版基本只会
落到 `%APPDATA%` 那一处**。全都写不进去时，宿主会往 stderr 打一行
`[ws_server] no writable location for .pet_ws_token; clients cannot authenticate`——
但正式版是 `windows_subsystem = "windows"`，**不会弹控制台**，界面上看不到这行字，
只有外部程序连不上时才会怀疑到它。

客户端读到的是上一次运行留下的旧令牌时，会收到明确的拒绝而不是静默失败
（`the pet host rejected the token from <文件>: Unauthorized: Token mismatch`），
重读一次即可——令牌是按进程生成的，把令牌读在宿主启动之前本来就是常态。

### 3.3 启动时不会做的事

- 不开机自启（代码中没有自启注册逻辑）。
- 不连接任何网络服务，总线只监听 `127.0.0.1`。
- 不在任务栏留窗口。
- **养成数值不是从零开始**：首次打开就是 Lv.3、经验 140/300、好感 78%、能量 88%、已完成 4 个番茄钟。

## 4. 主舞台怎么用

### 4.1 点击与拖拽

- **移动距离超过 6 像素才算拖拽**，否则算点击。
- **单击桌宠**：`+5 EXP`、好感 +2、心情 +2，播一声 `pat` 音（勿扰模式下不响），点击处飘出 `+5 EXP`。
  - 如果点中了感应区（内置的86只都有 `head` 和 `body`）：按该区定义播放动作与表情，
    随机抽一条该区的台词，气泡显示 3600 毫秒。
  - 如果点在了感应区之外：桌宠变 `happy` + 微笑，弹出引导你用右键菜单的气泡，显示 3400 毫秒。
- **拖拽移动窗口**：拖动中桌宠变惊讶表情并提示「⚡ 反重力牵引中！…」，松手后尝试磁吸到前台窗口顶栏。
  磁吸**只在伴生舱里「前景窗口标题栏磁吸攀爬」开关打开时**才生效；
  吸住时桌宠保持攀爬动作并提示已磁吸驻留。

### 4.2 星盘菜单

**打开方式**：右键桌宠、`Ctrl+M`、或点右下角「菜单」按钮。

视觉上是双轨反向旋转的星环，节点沿椭圆分布，每个节点有一条从中心射出的引导线。
每个一级菜单项显示序号和名称；**由外部程序注册的菜单项边框是绿的，
并带一个绿色呼吸灯**，一眼能认出哪些菜单不是内置的。

菜单项本身完全由 YAML 决定（见 10.2 与 11.2），当前配置的四组是
`互动养成`、`番茄专注`、`快捷工具`、`微调工坊`。

**交互规则**：

| 菜单项类型 | 点击后 |
| --- | --- |
| 有子菜单 | 展开底部的二级面板（标题形如 `SECTOR // <菜单名>`，右侧显示模块数）；**再次点击同一项收起** |
| 无子菜单但有动作 | 执行动作，然后**自动关闭整个星盘** |
| 中心 ✕ 或点星盘外的空白 | 关闭 |

打开时会自动选中第一个带子菜单的项。每执行一次动作额外 `+8 EXP`、好感 +2。

动作类型与效果：`emit` 发事件（内部事件会真的改变桌宠状态，外部事件则经 WebSocket 转发）；
`panel` 打开伴生控制台；`exec` / `open` / `url` 执行本地命令或打开链接，
**命令的标准输出会作为气泡文本显示**，执行失败则提示失败并露出惊讶表情。

### 4.3 语音气泡

桌宠只要有话要说就会弹气泡。触发来源包括：点击、拖拽、拖入文件、斜杠指令、健康提醒、
外部 WebSocket 指令、切换机体、升级、投喂、番茄钟起止，以及闲置时的随机闲聊。

气泡长这样：

- 顶部是优先级标签 `P0`~`P3`（`P0`/`P1` 用强调色）和桌宠代号
- 右侧有 12 条实时音频频谱柱
- 正文**打字机逐字显现**（每字 24 毫秒，带闪烁光标）
- 如果这条消息带快捷回复按钮，按钮在**打字结束后**才出现在底部

关闭方式：点气泡（打字中＝立刻显示全文，打完＝关闭）、点右上 ×、或按 `Esc`。

> 鼠标悬停在气泡上会刷新「用户活跃时间」，**顺带阻止桌宠进入休眠**。

### 4.4 状态坞

**上方状态药丸**的显示条件是：悬停桌宠 **或** 番茄钟正在运行 **或** 对话栏打开；
并且蓝图舱没开、当前也没有气泡（桌宠正在说话时状态坞会自动让位）。

药丸内容与可点项：

| 显示项 | 说明 |
| --- | --- |
| `Lv.N` | 悬停时提示当前经验 / 升级所需经验 |
| `好感 N%` | 只读 |
| `能量 N%` | 只读 |
| `专注 MM:SS` | **可点击**：运行中则暂停，未运行则直接开始一个 25 分钟专注 |
| `勿扰关` / `免打扰` | **可点击**：勿扰开关，切换时桌宠会有动作并播报 |

底部还有一条细进度线显示当前经验百分比。

**右下角 6 个按钮**（纯文字按钮，不使用 emoji 图标）：

| 按钮 | 作用 |
| --- | --- |
| 菜单 | 展开 / 收起星盘菜单 |
| 对话 | 唤出内联对话与指令舱 |
| 投喂 | 投喂「全息数据糖果」：+20 能量 / +8 好感 / +25 EXP |
| 伴生舱 | 打开伴生控制台 |
| 换宠物 | 循环切换到下一个机体 |
| 校准 | 开 / 关 CAD 蓝图微调舱 |

状态坞在鼠标离开桌宠后**不会立刻消失**：光标移到状态坞上的那一小段空隙里它仍然挂着，
光标停在别处超过约 1.2 秒才收回，所以从桌宠挪到按钮不需要抢时间。

**对话指令栏**：

- 输入 `/` 会弹出补全（最多 5 条），按 `Tab` 接受第一条
- 4 个快捷标签：25m专注 / 今日运势 / 投喂充能 / 系统巡检
- `↑` `↓` 翻阅历史指令（本地最多存 25 条）
- `Enter` 或点「发送」提交，`Esc` 关闭

**拖放提示**：把文件拖过窗口时全屏出现「量子吞噬门」，提示释放鼠标将文件注入当前桌宠。
松手后按文件数 `+25 EXP` / 好感 +5 / 心情 +4，并播报文件名。
没匹配到处理规则时也会给奖励，并提示已捕获外部载荷。

### 4.5 CAD 蓝图微调舱

打开后整窗变成 CAD 网格与十字准星，此时**普通拖拽移动被禁用**。

| 能调什么 | 说明 |
| --- | --- |
| 机体切换 | 顶部一排药丸按钮，直接切 |
| 滚轮缩放 / 拖拽位移 | 滚轮以 0.08 为步进缩放，范围 **0.45x~3x**；画布上拖拽改位移；实时显示 SCALE 与 OFFSET；「归零」恢复 1.0x / (0,0)。全部实时生效 |
| 框选定义 HitArea | 先从下拉选 `head 头部传感器` / `body 核心反应堆` / `hand 侧翼挂载点`，再在画布上框选 |
| 动作 / 光谱下拉 | 7 种动作（idle/happy/pat/feed/drag/climb/sleep）与 4 种表情（neutral/smile/surprised/sleepy） |
| 导出 | 「复制 YAML」写入剪贴板；「持久化写入」直接改 `pet.yaml` |

框选感应区的规则：**框小于 16 像素会被丢弃**；同名区域是**覆盖**而不是新增；
新建区域会自动带上动作（head＝pat，其余＝happy）、smile 表情和固定台词。
已有感应区显示为绿色虚线框，标签形如 `ZONE // 标签 (名称)`，右上角红色 `×` 可删除。

**关于放大**：缩放**不再受窗口大小限制**。桌宠窗口会跟着缩放一起变大，所以放大到 3 倍
也不会把宠物裁掉；窗口保持中心不动，只是向四周长开。状态坞、状态药丸与星盘仍固定在
原尺寸、居中跟随宠物，不会被推到角落。缩放下限 0.45x 保证宠物不会被缩到看不见。
窗口上限为 1280px，避免超大倍率吞掉整个桌面。

两个要注意的地方：

- 动作/表情下拉**不是预览**，它直接改写桌宠当前的动作与表情，会被下一次气泡动作覆盖。
- 「复制 YAML」在剪贴板被拒绝时**按钮毫无反应**（成功才会闪一下「✓ 已复制 YAML」）。
- 「持久化写入」失败时不会报错，只提示「蓝图参数已实时生效」——也就是说**参数仍然生效，只是没存盘**。

## 5. 伴生控制中心

点右下角「伴生舱」、托盘 `🎛️ 打开空间伴生控制中心`，或从星盘菜单的「打开控制面板」进入。
窗口标题栏可以拖动移动，右上角 ✕ 是收起入口（收起只是隐藏，进程仍在跑）。

底部常驻一个 `CMD ▸` 输入框 + TRANSMIT 按钮，可以发全息对话或斜杠指令。

四个页签：**🧬 神经突触舱**（默认首屏）、**🍅 专注与待办**、**❤️ 机体羁绊**、**🌐 网页与AI脑桥**。
四个页签都是已实现的功能，没有占位骨架。

### 5.1 🧬 神经突触舱

一个由配置驱动的通用控件渲染器，内置 7 个模块，卡片左右交错排布并用光束连到顶部核心。

每张卡片：`◂ ▸` 左右微调 8 像素（累计限 ±24 像素），`−` `+` 折叠展开，**双击卡片标题栏**也能折叠。

| 模块 | 类型 | 作用 |
| --- | --- | --- |
| 微内核神经总线 | 状态徽章 | 显示 `ONLINE // :端口 (N CONN)`，只读 |
| 前景窗口标题栏磁吸攀爬 | 开关 | 控制拖拽磁吸，关闭后保存进配置文件 |
| 全局物理鼠标穿透模式 | 开关 | 桌宠窗口完全不拦截鼠标 |
| 语音合成播报 (TTS) | 开关 | 气泡出现时朗读文本；用哪种声音去「🌐 网页与AI脑桥」的语音桥选 |
| WebGL 渲染时序策略 | 下拉 | 动态（空闲 24/活跃 60）、锁定 60、锁定 30 |
| 声波 RMS 口型同步增益 | 滑块 10~200% | 步进 5 |
| 空间战术指令矩阵 | 按钮组 | 全息脉冲播报 / 投射AR雷达 / 静默清除HUD |

- 「全息脉冲播报」让桌宠说一句「🎛️ 伴生神经突触控制中心已唤醒！」
- 「投射AR雷达」在 HUD 层画一个带 15 秒倒计时的锁定框
- 「静默清除HUD」清空所有标注

页面底部是「微内核实时遥测流」终端，显示启动日志、系统遥测和你每次操作的回执，
`PURGE` 可清空，超过 80 行自动丢弃最旧的。

### 5.2 🍅 专注与待办

**上半：番茄钟**

- 大号倒计时（MM:SS）+ 进度条，右上角显示 FOCUS 或 SHORT_BREAK
- 要填的字段：**当前专注目标**（文本，会同步回主窗口）、**自定义分钟数**（1~180）
- 按钮：自定义分钟专注 / ⚡45m 深度 / 🍵5m 小憩 / ⏸暂停·▶继续 / ⏹重置

**下半：待办矩阵**

- 要填：优先级下拉（🔥高优 / 💠常规 / 🌱低优）+ 任务文本，回车或点「+ 添加」
- 每条待办点勾选框**或**点文字都能切换完成，完成奖励 `+20 EXP`
- 顶部显示 `已完成/总数 DONE`，有已完成项时出现「清理已完成」
- 空态文案「暂无待办事项，享受无 Bug 的轻松时刻吧 ✨」
- 首次启动预置 **2 条**待办（体验星盘与机体切换 / 开启 25 分钟番茄冲刺）

### 5.3 ❤️ 机体羁绊

- **养成状态**：EXP 进度条、好感度、能量三条，右上角显示当前等级
- **三个动作**：
  - 投喂数据糖果：+20 能量 / +8 好感 / +25 EXP
  - 注入高能晶块：+45 能量 / +12 好感 / +45 EXP
  - 每日代码占卜：+15 EXP，播放运势气泡
- **姿态调试台**：6 个按钮（脉冲跃迁 / 触觉共鸣 / 能量吞噬 / 磁吸攀爬 / 休眠巡航 / 标准待机）。
  注意这是**真实播放**在桌宠身上，不是预览。
- **机体切换**：5 张卡片显示名称、模型类型、简介，点击即切换并弹出跃迁提示。
  卡片数量跟着 `pets/` 目录里的宠物数量走，自己放进去的宠物也会出现在这里。

### 5.4 🌐 网页与 AI 脑桥

**AI 网关配置**（1 个下拉 + 4 个字段 + 1 个开关 + 1 个测试按钮 + 记忆/流式两项）：

| 字段 | 说明 |
| --- | --- |
| 接口协议 | 决定请求怎么发、回复从哪个字段读。**换厂商不需要改代码** |
| API 地址 | 随协议变化，占位提示会跟着切换 |
| 模型名称 | 默认 `gpt-4o-mini` |
| API Key | 密码框；协议标「无需 Key」时这一项不参与判定 |
| 自定义人设 Prompt | 约束回复风格；留空则按当前宠物的 `persona` 自动生成 |
| 记忆轮数 | **0~20 轮**，默认 4 轮（= 最近 8 条消息）。填 0 就是不带记忆；超过 20 按 20 算；填非数字按默认算 |
| 逐字流式上屏 | 勾上后回复逐字出现在气泡里；关掉则等整段回来再显示 |
| 清空当前宠物记忆 | 只清当前这只宠物的历史，别的宠物不受影响 |

三种协议：

| 协议 | 覆盖范围 | 需要 Key | 流式 |
| --- | --- | --- | --- |
| `OpenAI 兼容`（默认） | OpenAI、DeepSeek、通义千问、智谱、Kimi、SiliconFlow、LM Studio、vLLM、one-api… | 是 | SSE，逐字 |
| `Anthropic Claude` | Claude 官方接口（`x-api-key` + 顶层 `system` 字段） | 是 | 事件流，逐字 |
| `Ollama 本地` | 本机 Ollama 的 `/api/chat`，**完全离线免费** | **否** | 逐行 JSON，逐字 |

三种协议的流式格式互不相同（`data:` 行 / `event:`+`data:` 行 / 每行一个 JSON），
宿主逐个解析，**解析不了的接口会优雅回落到整段返回**，不会卡住或报错。
关于失败边界：**还没吐出任何字**时失败会回落到整段请求重试；**已经开始吐字**后再断开，
保留已经上屏的那部分而不是重发（否则气泡会重打一遍）。

选了不认识的值会退回 `OpenAI 兼容`，不会报错。

勾选「启用远程 LLM」才会真正联网。右上角按钮是**连通性测试**，有 5 种状态：
`⚡ 测试连接` / `⚠️ 需填 Key` / `⏳ 请求中...` / `✓ 连通正常` / `✕ 连接失败`，2 秒后自动回到初始态。

三点要知道：

- **测试连通不会顺手把「启用远程 LLM」打开**，它是用一次性配置去探测的。
- 测试成功时桌宠会把大模型的回复当气泡说一遍。
- **宠物自带人格**：每只宠物可以在自己的 `pet.yaml` 里写 `persona:`（身份、性格、语气、禁忌），
  提示词由它自动生成，不需要在界面里手写。界面上的「自定义人设 Prompt」会覆盖它，
  但宠物若写了 `persona.system_prompt` 则以宠物为准。写法见
  [`宠物接入指南.md`](宠物接入指南.md)。
- **对话带记忆**：每只宠物的最近几轮问答会保留，按宠物分开存放，切宠物不会串台。
  记忆只记**真实模型的回复**，内置离线性格脑的回复不会写进去。
  在 `CMD ▸` 里发 `/reset` 清空当前宠物的记忆。

**语音桥 VOICE BRIDGE // 语音合成与语音识别**：合成与识别各自一个下拉，选完下面会冒出对应的参数框。

| 控件 | 作用 |
| --- | --- |
| 「测试朗读」 | 用当前合成方式念一句固定的话，结果写在下方状态行 |
| 「开始识别」 | 按当前识别方式录一段并转写；录音时显示电平条 |
| 「转写该文件」 | 只对 `本地命令行引擎` 出现：直接转写「可选」框里填的 wav 绝对路径，**没有麦克风也能验证链路** |
| 「识别完成后自动发送给宠物」 | 转写结果直接当聊天输入发出去（勿扰模式下不发） |

识别结果会先落在一个可编辑的输入框里，确认无误再点「发送」。
下拉项旁边会写清楚「未就绪：<原因>」，例如缺 Key、缺模型目录、当前环境不支持录音。

每种方式各需要什么，见 [7.2 声音](#72-声音)。

**网页投射**：输入网址 → MOUNT 或回车 → 上方 iframe 显示。未挂载时显示引导文案，
提示网页可调用 `window.PetBridge.act / say / system.exec / panel.open`。
`panel.open({ mode, title, url, schema })` 让面板内容自己再开一个面板——SDUI 描述会原样
穿过 Rust 层（宿主的 `PetActionPayload` 带 `schema` / `mode` / `title` 三个字段），
所以不随宿主发行的面板内容也能把自己的界面递进来。缺 `schema`（schema 模式）或
缺 `url`（url 模式）会在打开前就被拒掉，而不是弹一个空面板。
iframe 以 `sandbox="allow-scripts allow-forms allow-popups"` 加载，
所以远程网页**不能执行本地命令**，只有本机/同源页面能通过 postMessage 驱动桌宠。

## 6. 养成与番茄钟

### 6.1 初始状态

首次打开**不是零**：Lv.3、经验 140/300、好感 78%、能量 88%、已完成 4 个番茄钟。

### 6.2 经验获取

| 行为 | EXP | 好感 / 心情 |
| --- | --- | --- |
| 点击桌宠 | +5 | 好感 +2 / 心情 +2 |
| 拖入文件（每个文件） | +25 | 好感 +5 / 心情 +4 |
| 完成一条待办 | +20 | 好感 +2 / 心情 +3 |
| 完成一个专注番茄钟 | +60 | 好感 +5 / 心情 +8 |
| 每日运势占卜 | +15 | 好感 +3 / 心情 +5 |
| 在对话栏输入任意内容 | +6 | 好感 +1 / 心情 +1 |
| 执行任意菜单 / 动作 | +8 | 好感 +2 |

### 6.3 增长与衰减规则

- **升级**：经验够了立刻升级，升级所需经验按 **1.25 倍**递增；
  **升级瞬间能量直接拉满 100%**，播放升级音效并弹 5.2 秒庆祝气泡。
- 好感度 / 心情 / 能量上限 100%、下限 0%。
- ⚠️ **没有任何自动衰减。** 能量只因投喂增加、因升级拉满，**不会随时间下降**；
  好感度和心情也只增不减。如果你以为「不互动它会掉状态」，那是误解，不是 bug。

### 6.4 番茄钟

- **开始**：状态坞「专注」按钮（固定 25 分钟）、伴生舱四个按钮、`/focus [分钟] [任务]`、`/break [分钟]`、或点气泡上的快捷回复
- **时长**：1~180 分钟，超出会被夹紧；`/focus` 不带数字时用 25
- **暂停 / 重置**：`/stop` 或按钮；暂停即冻结倒计时；重置会把剩余时间**恢复为完整时长**并播报
- ⚠️ **只有主舞台窗口在真正计时**，伴生舱的操作通过窗口间总线转达给主窗口执行——
  所以**主窗口必须开着，番茄钟才会走**
- **结束**：倒计时归零自动触发。专注模式 → 已完成番茄数 +1、`+60 EXP`、
  7.5 秒气泡并附**两个快捷按钮**（`🍵 开启5m休息` / `🔥 再战25m`）；
  休息模式结束不加分，只提示并附 `🔥 开启25m专注`

番茄钟开始后：桌宠立刻变 `happy` + 微笑并播报「🍅 番茄专注已启动…」，
状态坞的「专注」计时开始走动并变成红底告警色，而且**即使鼠标不悬停桌宠，状态药丸也会一直显示**，
方便随时看剩余时间。

### 6.5 动作优先级

动作分 `P0 > P1 > P2 > P3`。高优先级动作会**打断**当前动作；
被打断且允许续播的动作会被放回队列开头继续播完，低优先级动作排队等待。

用户看到的现象是：桌宠同时被点击、拖文件、跑指令时，**不会话说到一半丢字，而是排队依次播报**。

**勿扰模式会拦掉 P3 闲聊类动作**，但升级、番茄完成这类重要提示仍然会弹出。

桌宠超过 5 秒无操作且没有动作或菜单展开时，帧率自动降到 24；任何点击、悬停、开菜单都立刻恢复 60。

### 6.6 数据保存

- 等级 / 经验 / 好感 / 能量 / 心情、待办列表写入**浏览器本地存储，重启保留**。
- ⚠️ **番茄钟进度不保存**，重启后回到 25:00。
- ⚠️ **清除浏览器数据会清空养成进度**。
- 跨窗口同步是实时的：在伴生舱里投喂、开关设置、启动番茄钟，主舞台桌宠立刻同步反应；
  反之在桌宠上操作，伴生舱的数值条、计时器、开关状态也跟着变。

换主题的三个入口：右下角「换宠物」循环切换、伴生舱「机体羁绊」页签点卡片、蓝图舱顶部药丸。
切机体即换主题，桌宠会提示「主题切换至 X」。

主题色同时作用于星盘、状态坞、气泡、伴生舱、HUD 标注框颜色与精灵粒子色。

**自带宠物的配色写在它自己的 `pet.yaml` 里**（`theme:` 段），不需要改任何源码；
没写 `theme:` 的宠物才会用上表里的内置配色。想加自己的宠物，见
[`宠物接入指南.md`](宠物接入指南.md)。

### 7.2 声音

**本项目不依赖任何音频文件**，所有声音都是实时合成的。

| 类型 | 触发 | 说明 |
| --- | --- | --- |
| UI 反馈音效 | 点击、投喂、升级、番茄钟起止 | Web Audio 振荡器现场合成短音 |
| 语音朗读（TTS） | 气泡出现时 | 四种做法任选，见下面两张表 |
| 语音识别（STT） | 舞台输入栏的「说话」按钮，或伴生舱「开始识别」 | 四种做法任选，见下面两张表 |
| 口型同步 | 说话时 / 正在听你说话时 | 有真实音频时用频谱分析驱动嘴型；无音频时用合成波形假装说话；录音时用麦克风电平驱动 |

**朗读的四种做法**（`audio.tts.provider`）：

| 取值 | 在哪念 | 需要准备什么 |
| --- | --- | --- |
| `web_speech`（出厂默认） | 操作系统自带的语音 | **零配置**，装上就能用 |
| `openai_compatible` | `POST /v1/audio/speech` | 接口地址 + 模型名 + 音色；Key 视服务而定 |
| `local_engine` | 本机命令行引擎，**完全离线** | 引擎 exe + 模型目录 |
| `none` | 不念 | 只显示气泡文字 |

**识别的四种做法**（`audio.stt.provider`）：

| 取值 | 在哪识别 | 需要准备什么 |
| --- | --- | --- |
| `none`（出厂默认） | 不识别 | —— |
| `web_speech` | 系统自带的识别服务，**多数实现会把音频发往厂商云端** | 联网 |
| `openai_compatible` | `POST /v1/audio/transcriptions` | 接口地址 + 模型名；Key 视服务而定 |
| `local_engine` | 本机命令行引擎，**完全离线** | 引擎 exe + 模型目录 |

出厂默认把识别关掉，是为了**避免一启动就弹麦克风授权**。
权限被拒时会告诉你权限名与去哪开，不会只丢一个错误码。

**两个识别入口，同一套流程**：

1. **舞台输入栏**（点状态坞的「对话」按钮或按 `Ctrl+K` 打开）——输入框左边多了一个
   「说话」按钮。**点一下开始，再点一下停止**；识别结果**只填进输入框，不会自动发送**，
   确认或改完再按回车。听的过程中按钮变成「停止」并亮红点，红点亮度跟麦克风电平走，
   **桌宠同时会跟着你说话一张一合地动嘴**，所以「它在听」这件事在角色身上直接看得见。
   `audio.stt.provider` 是 `none` 时按钮显示「未配置」并禁用，悬停给出未就绪原因
   （实测文案：按钮不可点，提示「未就绪：语音识别已关闭」）；把这一项改成 `web_speech`
   存盘后**无需重启**即生效，按钮变成「说话」，提示变成「系统识别（Web Speech，需联网）｜
   点击开始识别，再点一次停止；结果只填进输入框，不会自动发送」。
2. **伴生舱 → 🌐 网页与AI脑桥**——功能相同，另有「识别完成后自动发送给宠物」开关与
   「转写该文件」（不碰麦克风，直接转写一个 wav）。

> ⚠️ **`web_speech` 这条路没有电平**：音频在浏览器/系统手里，拿不到幅度，所以选它时
> 红点与嘴型都不会动——这不是坏了，是这条路径给不出这个信号。要看到嘴型跟着动，
> 用 `openai_compatible` 或 `local_engine`（这两条都走本机录音）。
>
> ✅ **`web_speech` 需要的接口，WebView2 里是有的**（2026-10-18 对 release 二进制实测）。
> 用 `python scripts/runtime-smoke.py` 启动宿主并逐页询问得到：三个窗口
> （主舞台 `tauri.localhost/`、伴生舱 `/companion.html`、HUD 覆盖层 `/hud.html`）里
> `window.SpeechRecognition` 与 `window.webkitSpeechRecognition` 都是 `function`，
> `navigator.mediaDevices.getUserMedia`、`MediaRecorder`、`AudioContext`、
> `speechSynthesis` 也都在；主舞台 `speechSynthesis.getVoices()` 返回 3 个音色。
> 所以这条路不是「这个运行环境没有那套接口」。
>
> ⚠️ **但「能不能真的识别出你说的话」仍未验证**：麦克风授权、联网可达性、识别准确率
> 都取决于你的机器与麦克风，本轮没有在真实麦克风上跑过一次完整识别，也没有点过那个按钮。

**开关在哪**：

1. **勿扰模式**（状态坞「勿扰关」或托盘 `🔕 切换勿扰隐匿模式`）——一键静音全部音效与朗读，并拦掉闲聊类气泡
2. **TTS 总开关**——伴生舱 → 🧬 神经突触舱 →「语音合成播报 (TTS)」
3. **换合成 / 识别方式与参数**——伴生舱 → 🌐 网页与AI脑桥 →「VOICE BRIDGE // 语音合成与语音识别」
4. **`audio.enable_lip_sync`** 这一项**没有界面开关**，只能改 `config/settings.yaml`
5. **口型幅度增益**——🧬 神经突触舱「声波 RMS 口型同步增益」滑块，10~200%

朗读失败（Key 没填、引擎路径不对、环境不支持…）时，**原因会直接写在气泡里**，
不会静默变成「宠物不说话」。同时嘴型照旧动，所以看起来仍然像是在说话。

**想完全离线用本地引擎**：仓库带了一个获取脚本，它会下载引擎与中文模型、跑一次
「合成 → 识别」闭环自检，并把填好绝对路径的配置片段打印出来：

```bash
python scripts/fetch_local_voice_engine.py --dest E:/AI/sherpa-onnx
```

把打印出的两段贴进 `config/settings.yaml`，保存即生效——**不需要重新编译，也不需要改源码**。
下载约 341 MB，最终留在磁盘上的是 2 个 exe（约 38 MB）加 2 个模型目录（约 100 MB）。
换成别的命令行引擎（piper、edge-tts CLI…）只改 `exe` 与 `args` 模板；
参数模板里可用的占位符见 `config/settings.yaml` 的注释。

以本机实际装出来的 `--dest E:/AI/sherpa-onnx` 为例，脚本解压后的布局是
`bin/sherpa-onnx-offline-tts.exe`、`bin/sherpa-onnx-offline.exe`、
`models/vits-piper-zh_CN-chaowen-medium-int8/`、`models/sherpa-onnx-paraformer-zh-small-2024-03-09/`。
因此合成与识别各贴这一段（**只需改 4 个空串，`args` 模板保持出厂值即可**）：

```yaml
audio:
  tts:
    provider: local_engine                        # 从 web_speech 改成这一行
    local:
      exe: "E:/AI/sherpa-onnx/bin/sherpa-onnx-offline-tts.exe"
      model_dir: "E:/AI/sherpa-onnx/models/vits-piper-zh_CN-chaowen-medium-int8"
  stt:
    provider: local_engine                        # 从 none 改成这一行；改成 web_speech 则走系统识别
    local:
      exe: "E:/AI/sherpa-onnx/bin/sherpa-onnx-offline.exe"
      model_dir: "E:/AI/sherpa-onnx/models/sherpa-onnx-paraformer-zh-small-2024-03-09"
```

> 路径两种斜杠都认（写成 `E:\AI\...` 也可以）；`model_dir` 里的 `*.onnx` 走的是
> 「取目录里第一个匹配文件」，所以模型换了文件名也不用改配置。
> 这两个 exe 是静态链接的，**目录里没有 dll 要一起带上**。

> 唯一会播放真实音频文件的情况：外部程序通过 `pet.act` 事件附带 `audio` 字段时。
> 走 `openai_compatible` 或 `local_engine` 时音频是读成字节再播放的，
> 所以**远程音频不会撞上 CORS**。

## 9. 托盘与窗口行为

### 9.1 系统托盘菜单

托盘图标右键（或点击）后出现 5 个菜单项。**这五项都是普通菜单项，没有勾选标记**——
鼠标穿透、勿扰的当前状态不会在菜单上打勾，只能从桌宠自身的行为上判断。

| 菜单原文 | 点了会发生什么 |
| --- | --- |
| `💠 召唤/归位桌面宠物` | 强制关闭鼠标穿透，把桌宠窗口显示出来并**移到屏幕中央**，然后同步状态给前端 |
| `🎛️ 打开空间伴生控制中心` | 显示并聚焦伴生面板 |
| `👻 切换全局鼠标穿透` | 开关「鼠标穿透桌宠窗口」 |
| `🔕 切换勿扰隐匿模式` | 切换勿扰标记 |
| `✕ 退出 AI-Pets` | 删除令牌文件并退出进程 |

注意第一项是「**召唤/归位**」：它会把桌宠从右下角挪到屏幕正中，不再回角落。

### 9.2 鼠标穿透

后端以 33Hz 推送光标位置，前端每帧做像素级命中测试：
**光标不在桌宠身上时自动开启穿透，回到桌宠身上自动关闭**。
蓝图舱、星盘菜单、对话栏任一打开时**强制关闭穿透**，保证面板可点。

另外：

- `Ctrl+Shift+T` 切换**全局永久穿透**（伴生舱也有同名开关）
- 桌宠点中窗口**不会**把你正在输入的窗口切走（宿主设了 `WS_EX_NOACTIVATE`）
- HUD 标注层**恒为 100% 鼠标穿透**，不拦截任何点击

### 9.3 贴边探头与窗口吸附

- **贴边探头**：有窗口进入全屏时桌宠自动贴到屏幕右缘只露一条边，退出全屏时回归。
  也可以用星盘菜单的 `👀 贴边探头测试` 手动开关——手动切换会播报，
  **全屏自动切换不播报**。受 `enable_fullscreen_edge_peek` 控制。
- **窗口吸附**：桌宠会挂到前台窗口顶部。以下三种情况**不会**吸附：
  没有前台窗口、前台是全屏程序、前台就是 AI-Pets 自己。
  全屏判定为「位置在 (0,0) 且尺寸覆盖整屏（屏幕下限 1280×720）」，
  所以全屏游戏里桌宠不会被误吸附。

### 9.4 关闭窗口 ≠ 退出

三个窗口被关闭时都只是**隐藏**，进程仍在后台运行、托盘仍在、总线与令牌仍然有效。
找回方式：

- 桌宠：托盘 `💠 召唤/归位桌面宠物`
- 伴生面板：托盘 `🎛️ 打开空间伴生控制中心`（或伴生舱右上 ✕ 只是收起）
- HUD：只能由外部程序再次发送 `hud.draw` 唤出

**唯一的正常退出方式是托盘菜单的 `✕ 退出 AI-Pets`。**
代码里没有其它退出入口——没有快捷键、没有菜单栏、没有命令行参数。

### 9.5 退出与重启之后

- **旧令牌立刻失效。** 令牌每次进程启动重新生成。正常退出时令牌文件会被删除；
  被任务管理器强杀则可能残留过期令牌，外部程序读到它会一直收到 `Unauthorized: Token mismatch`。
- **端口可能变。** 重启后从 9527 重新顺延，占用情况不同就落到不同端口。
  外部程序**不要硬编码端口**，应按 `9527..9537` 逐个尝试或从遥测接口读。
- **外部注册的菜单和 HUD 标注会被清空**，因为连接断开时宿主会对每个登记过的 app_id 发送
  `ws-menu-unregister` 与 `hud-clear`。外部程序需自行重连并重新注册。

3. ⚠️ **文件监听器创建失败时是静默的**，你在界面上收不到任何提示，
   表现就是「改了配置完全没反应」——这时重启宿主即可重新建立监听。

### 11.2 pet.yaml 字段

| 字段 | 含义 |
| --- | --- |
| `id` | 宠物标识。**宿主实际用的是目录名**，清单里的 `id` 不参与校验 |
| `name` | 显示名 |
| `alias` | 短名，全局唯一。`/pet <alias>` 直接切到这只 |
| `cluster` | 分组名，伴生舱的机体列表按它分组 |
| `description` | 一句话设定描述 |
| `model.entry` | 主模型文件（内置的86只都是 `idle.png`） |
| `model.scale` / `model.offset` / `model.fps` | 缩放、位移、帧率 |
| `model.animations.<名字>` | 动作表。内置的86只提供 `idle` / `happy` / `pat` / `feed` / `drag` / `climb` / `sleep`；`idle`、`drag`、`climb`、`sleep` 循环，`happy`、`pat`、`feed` 播一次（1800–2600 毫秒） |
| `model.animations.<名字>.frames` / `.fps` | **帧条**：一张图里有几帧、每秒几帧。省略按单帧处理，`fps` 默认 12 |
| `expressions.<名字>.tint` | 表情着色。内置的86只有 `neutral` / `smile` / `surprised` / `sleepy`，取值是 `0x` 前缀十六进制 |
| `theme` | **这只宠物自己的配色**。写了就用它，没写才回落到内置默认配色。改配色不需要改源码，见 [7.1](#71-主题) |

| `drop_handlers[]` | 拖文件到桌宠身上的反应。含 `extensions[]`（`.py .rs .ts .js .vue .json .yaml .yml .md .txt` 或 `["*"]` 兜底）、`motion`/`expression`、`bubble_template`（`{filename}` 是文件名占位符）、`action` |
| `menus[]` | 这只宠物专属的菜单项，结构与 `global_menu.yaml` 相同 |

`theme` 与 `persona` 的完整字段说明、以及 `voice` 的写法示例，见
[`宠物接入指南.md`](宠物接入指南.md)。

> 内置的86只都写了 `theme` 与 `persona`；**目前没有内置宠物用到 `voice`**，
> 这个字段是给第三方宠物包准备的。

### 11.3 新增一只宠物

1. 新建 `pets/<id>/` 目录，放入模型文件和 `pet.yaml`；**目录名就是 id**。
2. `pet.yaml` 里的 `model.entry` 必须指向真实存在的文件，`animations` 与 `expressions`
   要覆盖实际用到的动作名与表情名。
3. id 只能由**字母、数字、下划线、连字符**组成，长度不超过 64 个字符。
   字母不限 ASCII，所以中文目录名可以用。

放进去就完事——**新宠物在应用界面、`/pet <id>` 指令和外部总线的 `switch_pet` 动作里
都能直接切到**，不需要改任何代码，也不需要重启：

```
/pet yin            ← 银羽的短名，直接发这个就能切过去
```

短名写在宠物自己的 `pet.yaml` 里（`alias`），全局唯一；`/pet` 先按短名找，找不到再按目录名找。

外部程序发 `switch_pet` 时如果写了个不存在的 id，会收到
`Unknown pet_id '<你传的 id>': no folder named that under <宿主解析到的 pets 目录>`；
id 里带了路径分隔符、`.`、`..` 或控制字符的会被直接拒掉。

## 12. 外部程序接入

宿主在 `127.0.0.1` 上开一个本地 WebSocket 总线，外部程序可以投递动作、菜单、面板内容和屏幕标注。

### 12.1 连接与鉴权

- **端口**：从 `host.ws_port_range` 起点顺延，**不要硬编码**，逐个尝试或从遥测接口读。
- **令牌**：每次进程启动重新生成，写在 `.pet_ws_token`（见 3.2）。
  **每一条入站文本报文都必须携带 `token` 字段**，值与令牌完全相等；
  缺失、空串、大小写不同、少一位、多一位一律拒绝，回复
  `{"status":"error","reason":"Unauthorized: Token mismatch"}`。
  鉴权发生在方法分发**之前**，热插拔方法也不例外。
- **握手 Origin**：带了 `Origin` 头就按解析后的主机名精确比对。放行
  `http://localhost`、`http://127.0.0.1`、`tauri://localhost`、`https://tauri.localhost`（端口任意）；
  其余一律 403。**不带 `Origin` 头的非浏览器客户端不受这条限制**，仍受令牌约束。
  只前缀相同的 `http://localhost.attacker.test` 之类会被拒绝。

### 12.2 支持的方法

| 方法 | 作用 |
| --- | --- |
| `pet.act` | 让宠物演一段动作并说话 |
| `pet.say` / `speak` | 弹语音气泡（两个名字等价） |
| `pet.driver` | 取得／归还角色决定权（`params.action`：`attach` 默认，`detach` 归还） |
| `menu.register` | 在应用内菜单注册外部菜单项 |
| `menu.unregister` | 注销该 app_id 的外部菜单 |
| `panel.open` | 立刻显示伴生面板并把参数投给它 |
| `panel.update` | 向伴生面板推送状态 |
| `hud.draw` | 立刻显示全屏 HUD 并画标注 |
| `hud.clear` | 清除 HUD 标注 |

不认识的方法名不会报错，也不会执行任何东西，但**依然会回一个 `status: "ok"`**——
外部程序不要把它当成执行成功的凭据。

**驱动权**（`pet.driver`）是唯一一个会改变宿主自身行为的声明：取得租约期间宿主**完全停掉**
自己的自主行为（走神台词、补水与久坐提醒、困倦入睡），因为两个决定者共用一个角色会得到一只
自相矛盾的宠物——驱动刚说完一句，宿主紧接着冒出一句不相干的提醒。只有持有者能归还；连接
断掉（进程退出、卡住、不再回应心跳）即自动归还。租约**不拦截 `pet.act`**：任何客户端仍可照旧
发动作，改变的只是宿主是否自己生成动作。前端收到 `pet-driver-changed`，`get_system_telemetry`
的 `driver_app_id` 报告当前持有者。

HUD 标注支持 `box`（带四角括号、扫描激光线、中心准星）与 `arrow`（带箭头的虚线）两种类型，
字段包括 `id` / `app_id` / `type` / `x` / `y` / `w` / `h` / `color` / `label` / `sublabel` / `countdownSec`。

### 12.3 白名单动作

报文带 `msg_type: "safe_action"` 时走白名单，可用的 `action_id` 只有 8 个：
`open_companion`、`toggle_studio`、`switch_emotion`、`switch_pet`、`open_official_docs`、
`trigger_greeting`、`start_pomodoro`、`trigger_scan`。

三点要注意：

- **除 `open_official_docs` 外，宿主侧这些动作只回一个字符串**，不改窗口、不改状态机，
  真正生效的是前端收到消息后的处理。
- `switch_emotion` 只接受 `idle`、`happy`、`angry`、`glitch`、`speaking`、
  `sleep`、`smile`、`surprised`、`sleepy`、`neutral`，写错会收到
  `Disallowed emotion identifier: X`。
- `switch_pet` **不限于内置宠物**：只要 `pets/<id>/` 目录真实存在就能切，
  用你自己放进去的 id 也可以。判定分两步：
  1. **形状**——不能为空、不超过 64 字符、只允许字母数字与 `_` `-`
     （字母不限 ASCII，中文目录名可用）；带路径分隔符、`.`、`..` 或控制字符的会被拒掉。
     三种回绝原文是 `Invalid pet_id: empty`、
     `Invalid pet_id: longer than 64 characters`、
     `Invalid pet_id '<转义后的原值>': only letters, digits, '_' and '-' are allowed`。
  2. **存在性**——形状合法但 `pets/<id>/pet.yaml` 不存在时回复
     `Unknown pet_id '<转义后的原值>': no pet folder named that under <宿主解析到的 pets 目录> (a pet folder is <id>/pet.yaml)`。
     判据用的是 `<id>/pet.yaml` 而不是「同名目录」：宿主装载宠物列表读的就是这个文件，
     目录建了但清单没放的话，外部切换会被接受、界面却根本不认识这只宠物。
     这一步不能省：宿主早先只做形状校验，于是不存在的 id 也会回 `status: "ok"`，
     而前端把「找不到」当成无事发生，外部程序会以为切换成功了。
     报错里带上被搜索的目录，是为了让「我明明放进去了」这类问题一眼能查出是放错了地方。

### 12.4 面板控件（`panel.open` 的 schema）

`panel.open` 里那个 `schema` 才是面板内容。它是一份 **SDUI 描述**，宿主不解释业务含义，
只按类型渲染，所以外部程序的界面**不需要宿主为它改一行代码**：

```json
{
  "app_id": "your-app",
  "title": "面板标题",
  "subtitle": "副标题（可选）",
  "widgets": [
    { "id": "bus", "type": "status_badge", "label": "总线", "value": "ONLINE", "tone": "success" },
    { "id": "climb", "type": "switch", "label": "窗口攀爬", "value": true,
      "effect": { "kind": "setting", "setting": "window_climbing" } },
    { "id": "mode", "type": "select", "label": "模式", "value": "dynamic",
      "options": [{ "label": "动态", "value": "dynamic" }] },
    { "id": "gain", "type": "slider", "label": "增益", "value": 80, "min": 10, "max": 200, "step": 5, "unit": "%",
      "effect": { "kind": "setting", "setting": "voice_gain" } },
    { "id": "actions", "type": "button_group", "label": "操作",
      "buttons": [{ "id": "scan", "label": "扫描", "variant": "primary",
                    "effect": { "kind": "hud_draw", "annotations": [
                      { "id": "a1", "type": "box", "x": 600, "y": 240, "w": 320, "h": 180,
                        "label": "目标区域", "countdownSec": 12 } ] } }] },
    { "id": "log", "type": "log_viewer", "label": "日志", "lines": ["就绪"] },
    { "id": "token", "type": "text_input", "label": "访问令牌", "value": "",
      "placeholder": "粘贴 token", "submit_label": "提交" },
    { "id": "voice_group", "type": "container", "label": "语音设置", "layout": "row",
      "children": [
        { "id": "tts_on", "type": "switch", "label": "朗读气泡", "value": true,
          "effect": { "kind": "setting", "setting": "tts" } },
        { "id": "tts_mode", "type": "select", "label": "音色档位", "value": "default",
          "options": [{ "label": "默认", "value": "default" }] }
      ] }
  ]
}
```

八种控件：

| `type` | 必填字段 | 可选字段 |
| --- | --- | --- |
| `status_badge` | `id` `label` `value` | `tone`：`success` / `info` / `warning` / `danger` |
| `switch` | `id` `label` `value`（布尔） | `description` `effect` |
| `select` | `id` `label` `value` `options[]`（每项 `label` + `value`） | `effect` |
| `slider` | `id` `label` `value` `min` `max` | `step` `unit` `effect` |
| `button_group` | `id` `label` `buttons[]`（每项 `id` + `label`） | 按钮的 `variant`（`primary` / `secondary` / `danger`）与 `effect` |
| `log_viewer` | `id` `label` `lines[]` | —— |
| `text_input` | `id` `label` `value`（字符串） | `placeholder` `description` `multiline` `submit_label` `effect` |
| `container` | `id` `children[]` | `label` `description` `layout`：`stack`（默认，竖排）/ `row`（横排换行） |

`container` 的 `children` 就是同一套控件，所以可以层层套。**最多套 4 层**，再深的
那一层会显示「嵌套层数超过 4 层」，而不是把面板渲染崩掉——schema 是外部数据，
深度不设上限等于让面板决定宿主递归多深。
`container` 本身没有 `effect`：副作用挂在能产生值的控件上，容器只是个布局盒子。

`text_input` 是**唯一能让外部程序向用户索要新东西**的控件（令牌、路径、一段提示词……）。
它的 `value` 上限 2000 字符；`multiline: true` 时用 `Ctrl+Enter` 提交，
写了 `submit_label` 会多出一个提交按钮。

#### 控件副作用（`effect`）

**控件做了什么由 `effect` 决定，与 `id` 叫什么完全无关。** 宿主早先是拿 `id` 去比一张
写死在渲染层里的名单（`enable_climb` / `enable_tts` / `fps_mode` / `voice_gain` …），
别的面板写同名 id 才有效、写别的 id 就静默无操作。现在改成 schema 自己声明：

| `effect.kind` | 附加字段 | 作用 |
| --- | --- | --- |
| `setting` | `setting`：`window_climbing` / `click_through` / `tts` / `fps_mode` / `voice_gain` | 把**控件当前值**写进对应宿主设置并落盘 |
| `say` | `text`（可选）`durationMs`（可选） | 让桌宠弹一条气泡；不写 `text` 就用控件自己的字符串值 |
| `hud_draw` | `annotations[]` | 往 HUD 标注层画框/箭头（字段见 12.2） |
| `hud_clear` | —— | 清空 HUD 标注层 |

三条边界：

- **只声明不认领的 id 也能工作**：`id` 现在只用作事件回传的标识和折叠状态，随便起名。
- **参数类型不符会被拒并说明**：比如 `setting: "fps_mode"` 的 select 值不是
  `dynamic` / `60` / `30` 三者之一，面板日志里会出现一行
  `[未执行] <控件名>: 副作用参数类型不符：fps_mode 需要 …`，而不是什么都不发生。
  未知的 `effect.kind` / `setting` 同样会打印一行并列出可用值。
- **可用的副作用是一个封闭集合**：面板内容来自外部，所以「让宿主执行任意命令」这类
  能力刻意没有提供——需要它就用宠物菜单的 `exec` 动作，那是由用户自己的 `pet.yaml` 授权的。

声明了 `effect` 的控件在面板打开时会**从宿主实时状态回读初值**，所以不需要自己同步
（这也是为什么 `id` 不必叫 `voice_gain` 也能显示正确的增益）。

**加一种新控件要改几个文件**：两个。控件名加进 `src/types/pet.d.ts` 的 `SduiWidget` 联合，
渲染分支加进 `src/companion/SduiWidgetView.vue`。副作用不用动——声明式的 `effect`
已经在渲染层之外解析；面板自己的状态同步也不用动——回读是按 `effect.setting` 找的，
不认 id。改完 typecheck 会把漏掉的分支报出来。

用户在面板上操作后，宿主把这些事件**回发给该 `app_id` 的连接**：

| 事件 | 载荷 | 什么时候发 |
| --- | --- | --- |
| `panel.state_changed` | `widget_id` + `value` | 开关、下拉、滑块、文本框的值变了 |
| `panel.text_submitted` | `widget_id` + `value` | 文本框按回车（或点提交按钮）时 |
| `panel.button_clicked` | `widget_id` + `button_id` + `label` | 按钮组的某个按钮被点 |

宿主按 `app_id` 路由：`schema.app_id` 写了就**只发给那一个连接**；`app_id` 为空时会退化成广播，
**所有连接都会收到**，这时才需要外部程序自己按 `params.app_id` 过滤。
没有活动连接时这些事件直接丢弃，不会报错——所以别把「没收到」当成「用户没操作」。

### 12.5 联调脚本

仓库里的 `test_external_app.py` 提供三种模式：

| 命令 | 作用 | 需要宿主在跑吗 |
| --- | --- | --- |
| `python test_external_app.py` | 5 步协议联调：说话 → 切情绪 → 注册菜单 → 画 HUD → 更新面板 | 需要 |
| `python test_external_app.py --authcheck` | 负向测试：发 5 条**必须被拒**的报文，逐条打印 `[PASS]`/`[FAIL]` | 需要 |
| `python test_external_app.py --selftest` | 离线自检：在本地 mock 宿主上跑同样的 5 步 | 不需要 |

脚本会在 4 个位置找令牌：当前目录 → `%APPDATA%\com.aipets.microkernel\` →
`%XDG_DATA_HOME%` → `~/.local/share/com.aipets.microkernel/`。
**在宿主的工作目录里运行脚本最省事**，否则它可能找不到令牌。

## 13. 常见问题

### 13.1 界面与互动

**桌宠不见了 / 面板打不开**
窗口被关闭只是隐藏，进程还在。用托盘 `💠 召唤/归位桌面宠物` 和
`🎛️ 打开空间伴生控制中心` 唤回。HUD 窗口无法从托盘唤出，只能由外部程序重新发送 `hud.draw`。

**桌宠挡住工作区，点不到下面的东西**
鼠标移开桌宠就会自动穿透；或托盘 `👻 切换全局鼠标穿透`；或 `Ctrl+Shift+T` 开全局永久穿透。

**点桌宠不会把我正在输入的窗口切走**
设计如此。桌宠窗口设了 `WS_EX_NOACTIVATE`，点击它不抢输入焦点，也不进任务栏和 Alt+Tab。

**桌宠总是自己跑掉**
托盘第一项是「召唤/**归位**」而不是「回到右下角」，它会把桌宠移到屏幕正中。
右下角位置只在启动时由宿主自动放置。

**星盘菜单展开是空的，只有一个 ✕**
菜单项全部来自 YAML。配置加载失败时内置兜底菜单是空的。检查 `_up_\config\global_menu.yaml` 是否存在。

**按了「投射AR雷达」但什么都没出现**
伴生舱的「投射AR雷达」只广播绘制事件，**不会唤出 HUD 窗口**；
HUD 当前不可见时你就看不到。想直接看到 HUD，用 `/scan` 指令，它会显式唤出窗口。

**蓝图舱的「复制 YAML」按钮点了没反应**
剪贴板被拒绝时按钮无任何反馈。改用「持久化写入」直接改 `pet.yaml`。
注意写入失败也**不报错**，只提示「蓝图参数已实时生效」——参数照样生效，只是没存盘。

**找不到音量滑块**
**没有**音量调节界面。`volume` 只能由外部程序通过总线修改。

**找不到「口型同步」的开关**
`audio.enable_lip_sync` 这个配置项**没有任何用户可见开关**，只能改 YAML。
伴生舱里能调的只有「口型同步增益」（10~200%）和「语音合成播报 (TTS)」这个总开关。

### 13.2 养成

**能量/好感度一直不掉，是不是坏了**
没坏。**这套数值没有任何自动衰减**，只增不减（能量有 100% 上限）。
能量只因投喂增加、因升级直接拉满。

**「心情」这个数值在哪看**
**四个界面里都没有显示它**，只有好感度、能量、经验、等级四条可见数值。
它一直在后台累积。

**清除浏览器数据后养成进度没了**
养成数据存在浏览器本地存储里，清掉就没了。番茄钟进度本来就不保存，重启后回到 25:00。

**番茄钟不动了**
只有主舞台窗口在真正计时。确认桌宠窗口还在（可能只是被隐藏了，用托盘召唤回来）。

**首次打开为什么不是 Lv.1**
初始值就是 Lv.3、经验 140/300、好感 78%、能量 88%、已完成 4 个番茄钟，
待办里还预置了 2 条。

### 13.3 安装与启动

**MSI 安装返回 1603 / Error 1925**
MSI 是 per-machine 包，需要管理员权限，这是预期行为。
想给不需要管理员权限的用户分发，请改用 NSIS 包。

**白屏 / connection refused**
二进制不是带 `custom-protocol` 特性构建的，窗口去连 Vite dev server 了。
需要 `npm run tauri build` 打包，或 `cargo build --release --features custom-protocol`。

**改了 settings.yaml 没反应**
- `host.ws_port_range` 和 `host.heartbeat_timeout_sec` 宿主只在启动时读一次，**必须重启**。
- 其它字段热重载；但文件监听器创建失败时是静默的，这时重启宿主即可恢复。

**桌宠在浏览器预览里看不到 Live2D / Spine / VRM**
`npm run dev` 的浏览器预览模式下，这些运行时从 CDN 加载，离线不可用。
只有打包后的桌面端能正常用。

### 13.4 外部程序

**提示找不到令牌**
宿主没启动，或令牌写在脚本没找的路径上。在宿主的工作目录里运行脚本，
或直接去 `%APPDATA%\com.aipets.microkernel\.pet_ws_token` 取。

**报 `Unauthorized: Token mismatch`**
令牌是上一次的。删掉残留的 `.pet_ws_token`、重启宿主、再重新读取。
宿主被强杀时不会清理令牌文件，这是最常见的原因。

**握手被拒，收到 HTTP `403 Forbidden Origin`**
`Origin` 不在白名单。浏览器场景改用 `http://localhost`、`tauri://localhost` 或
`https://tauri.localhost`；非浏览器客户端干脆**不要发 `Origin` 头**。

**整个端口段都连不上**
`host.ws_port_range` 整段被占用或被安全软件拦截。改 `config/settings.yaml` 的
`host.ws_port_range`，然后**重启宿主**。

**拖代码文件到桌宠身上报错 `Failed to execute 'python': ...`**
投放 `.py .rs .ts .js .vue .json .yaml .yml .md .txt` 这类扩展名的文件时，
宿主会真的起 `python` 进程去解析它。机器上没有可用的 `python` / `python3` 就会报这个错。

**切不到自己放进来的宠物**
确认目录名与 id 只由字母数字和 `_` `-` 组成（中文也可以）。发
`/pet <目录名>` 试试——若回 `Unknown pet_id`，说明宿主没扫到这个目录；
若回 `Invalid pet_id`，说明目录名里有不允许的字符。

### 13.5 语音与 AI 对话

**桌宠不说话**
先看气泡里有没有一行小字。朗读失败的原因**直接写在气泡里**（Key 没填、引擎路径不对、
浏览器不支持…），照着改配置即可。气泡里没那行字，说明是 `audio.enable_tts` 关了，
或者开了勿扰模式。

**「开始识别」点了没反应 / 没弹麦克风授权**
`audio.stt.provider` 出厂是 `none`。先去伴生舱 → 🌐 网页与AI脑桥 → 语音桥选一种识别方式。
选完那行提示会告诉你还缺什么。

**麦克风权限被拒了**
提示里会写明是哪种权限、去系统的哪个位置开。改完权限后**重开桌宠窗口**再试。
实在拿不到麦克风，也可以用「转写该文件」直接传一个 wav 验证识别链路。

**本地引擎报找不到程序 / 路径不存在**
`exe` 必须填**绝对路径**，别填相对路径或只填名字。最省事的做法是跑
`python scripts/fetch_local_voice_engine.py --dest E:/AI/sherpa-onnx`，
让它把填好路径的配置片段直接打印出来。

**本地合成怎么要等好几秒**
`local_engine` 每次朗读都会**新起一个进程并加载模型**。本机实测：一句 13 个字的短句，
sherpa-onnx 用 int8 中文模型约 3.6 秒出 3.8 秒音频。要更快就得换更小的模型，
或者改用常驻服务的 `openai_compatible`（把本地 TTS 服务器当接口调）。

**换了宠物，AI 就不记得刚才聊了什么**
这是设计如此：对话记忆**按宠物分开存放**，切回来还在。想主动清空就发 `/reset`。
离线性格脑的回复不会写进记忆，只有真实大模型的回复才会。

## 14. 已知限制

- 没有开机自启功能。
- **没有独立的设置界面**：所有可调项都在 `config/` 下的 YAML 里；
  少量常用项可以在伴生舱里直接改，改完会写回同一个 YAML。
- `inline_hud`、`studio_mode`、`high_dpi`、`audio.enable_lip_sync`、`audio.rms_smoothing`
  这五项**没有任何用户可见开关**，只能改 YAML。
- 没有音量滑块。
- 内置宠物全部是 `sprite` 类型；Live2D / Spine / VRM 适配层代码存在，但没有内置资产使用它们。
- 白名单动作里除 `open_official_docs` 外都只是回字符串，实际表现依赖前端。
- 不认识的 `method` 也会回 `status: "ok"`，不代表被执行。
- 养成数据存在浏览器本地存储，清除浏览器数据即丢失。
- 本地语音引擎是**外部程序**：宿主不打包它，需要自己跑获取脚本下载；
  **引擎与两个模型各自带了什么许可声明、以及对外分发前要人工确认哪些**，见 7.3 节。
- `local_engine` 每次朗读/识别都要新起进程，**单次 3~5 秒起步**，不适合要求即时响应的场景。
- AI 对话**可以逐字流式上屏**（伴生舱 → 🌐 网页与AI脑桥 →「逐字流式上屏」，默认开），
  但**只有支持流式的接口才有这个效果**：把开关关掉、或所选接口只回整段时，
  回复仍是一次性出现。流式期间气泡会长时间挂着，收到第一个字之前失败会回落到整段请求
  （避免一个字都没吐就断在半路），**已经开始吐字之后**再断则保留已收到的部分而不是重发。
- 对话记忆**轮数可以在界面上调**（「记忆轮数」，0~20 轮，默认 4 轮 = 最近 8 条消息），
  旁边的「清空当前宠物记忆」按钮按当前宠物清空，`/reset` 指令做同一件事。
  另外**单条消息超过 500 字符会被截断**（写死在代码里，没有开关），
  记忆按宠物分桶存在浏览器本地存储里，清掉浏览器数据即丢失，也不能导出。
