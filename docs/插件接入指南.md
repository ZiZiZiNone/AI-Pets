# 插件接入指南

本文回答一个问题：**怎么给 AI-Pets 加一个自己的插件，且不需要改任何源码。**

答案是：一个插件就是 `plugins/` 下的一个文件夹。文件夹里放一份 `plugin.yaml`——**清单**，
写清插件是谁、它要申请哪些权限。清单旁边可以放插件本体（一个连总线发消息的程序）。

插件本身**不画界面**：它只描述「要显示什么」，宿主决定怎么显示。权限也不是插件自己说了算——
清单里写的叫**申请**，用户在伴生舱 → 🧩 插件 页签逐项点过之后才叫**批准**，真正生效的是两者
的交集。Rust 总线按这张表强制，越权调用一律被拒。

## 30 秒接入

### 第 1 步：建目录

在仓库的 `plugins/` 下新建一个文件夹，**文件夹名就是插件 ID**：

```text
plugins/
├── demo_external/        ← 仓库自带的示例插件
└── hello_pet/            ← 你自己的
    ├── plugin.yaml
    └── hello_pet.py      ← 插件本体（可选）
```

宿主会先找仓库自带的 `plugins/`，再找 `config/settings.yaml` 里 `host.plugins_dirs` 声明的目录
（与 `host.pets_dirs` 同一套写法，默认留空）。**同一个 id 出现在两处时，自带的那份生效**，
后面那份会被跳过并在日志里说明。

### 第 2 步：写 plugin.yaml

复制下面这段，改掉 `id`（必须与文件夹同名）、`name` 即可：

```yaml
id: hello_pet
name: 打个招呼
version: 1.0.0
description: 让桌宠的气泡说一句你好。
permissions:
  - pet:speak
```

`permissions` 里写的是**申请**。插件还没生效——它在等用户点头。

### 第 3 步：批准

- **在界面上**：伴生舱 → 🧩 插件 页签里找到这个插件，逐项同意。
- **直接写批准表**：在 `config/settings.yaml` 的 `host.plugin_approvals` 里加一行，
  或写一份 `plugins/approvals.json`（见[权限怎么生效](#权限怎么生效)）。

### 第 4 步：用它

插件本体连上总线、以插件 id 作为 `app_id` 发消息，宿主按权限表放行并渲染：

```json
{
  "token": "<令牌>",
  "jsonrpc": "2.0",
  "id": 1,
  "app_id": "hello_pet",
  "method": "pet.say",
  "params": { "text": "你好！", "duration_ms": 4000, "priority": "P2" }
}
```

桌宠的气泡就会显示这句话。**不需要重启宿主，不需要改任何源码。**

不想用了，把 `plugins/hello_pet/` 目录删掉即可。

## plugin.yaml 字段全解

`plugins/<id>/plugin.yaml` 顶层是一个键值映射。**宿主认识的顶层字段只有五个**：
`id` `name` `version` `description` `permissions`。

下表的报错文案是伴生舱插件页签「MANIFEST ISSUES // 清单异常」里显示的原文。

| 字段 | 必填 | 规则 | 违反后的报错文案 |
| --- | --- | --- | --- |
| `id` | 是 | 非空字符串；**必须以小写字母或数字开头**，只能包含小写字母、数字、下划线 `_`、连字符 `-`；长度 **2~64**；**必须等于所在目录名** | `清单缺少 id`<br>`id 必须以小写字母或数字开头，只能包含小写字母、数字、下划线和连字符，长度 2~64`<br>`id 与目录名 {目录名} 不一致` |
| `name` | 是 | 非空字符串，**不超过 64 个字符**。界面上显示的名字 | `清单缺少 name`<br>`name 必须是非空字符串`<br>`name 不能超过 64 个字符` |
| `version` | 是 | `1.2.3` 这样的三段数字，可带 `-beta.1` 这样的预发布后缀 | `清单缺少 version`<br>`version 必须是 1.2.3 这样的三段数字，可带 -beta.1 这样的预发布后缀` |
| `description` | 建议填 | 字符串。**宿主靠它向用户解释这个插件要什么**，界面上直接显示这一句 | `description 必须是字符串，已忽略` |
| `permissions` | 可选 | **字符串数组**，每项一个权限名；权限名必须在白名单内；重复的只算一次 | `permissions 必须是数组`<br>`permissions 里出现了非字符串项：{值}`<br>`未知权限：{权限名}` |

三条要知道的：

- **`id` 不等于目录名，这份清单直接不算数。** 判据是目录名，与宠物包的判据一致
  （`pets/<id>/pet.yaml` 也是目录名说了算）。
- **未知权限名会让整份清单不算数**（不是忽略那一条）：否则用户看到的权限列表会比插件真正要的短，
  批准下来的东西和插件想用的东西对不上。
- **不认识的顶层键只提示、不拦下**：清单照常加载，页签的「清单异常」里会列一条
  `未知字段 {键名}，已忽略`。

### 自检脚本多认的那几种写法

`scripts/doctor.py` 与 `scripts/plugin-harness.py` 是独立实现，容错比宿主宽一些。写插件时以
**宿主的写法为准**（上一节的表格），下面这些是两边目前不一致的地方：

| 写法 | 宿主（伴生舱页签） | 自检脚本 |
| --- | --- | --- |
| `permissions` 写成表（`- permission: pet:speak` + `reason: …`） | **不认**：报 `permissions 里出现了非字符串项：…`，插件进不了页签 | 认，且会把 `reason` 打给作者看 |
| `permissions` 只写权限名的字符串 | 认 | 认（此时没有申请理由，脚本会提醒一条） |
| 顶层多写 `author` / `homepage` / `icon` | 报「未知字段，已忽略」 | 当作元信息，不提示 |
| 顶层写 `entry`（插件本体入口） | 报「未知字段，已忽略」 | 认，并且要求它指向的文件真实存在，否则报 `entry 指向的文件不存在：{入口}` |

> ⚠️ **仓库自带的 `plugins/demo_external/plugin.yaml` 用的是表写法**（带 `reason`），
> 所以它目前能通过自检脚本，但在伴生舱插件页签里会显示为一条「清单异常」。
> **想让它在页签里正常出现，把 `permissions` 改成字符串列表**（或让解析器也认表写法）。

## 权限表

宿主一共认六个权限。它们与总线方法是一一对应的：

| 权限 | 对应的总线方法 | 拿它能干什么 |
| --- | --- | --- |
| `pet:act` | `pet.act` | 让桌宠演一段动作并说话。可用字段：`motion`（动作名）、`expression`（表情）、`text`（台词）、`audio`（音频）、`duration_ms`（气泡时长）、`priority`（`P0`~`P3`）、`resume_after_interrupt` |
| `pet:speak` | `pet.say` / `speak` | 弹一条语音气泡。可用字段：`text`、`duration_ms`、`priority`。**只说话，不改动作与表情**（固定 `happy` + `smile`） |
| `pet:driver` | `pet.driver` | 取得／归还「角色决定权」。`attach` 取得租约，`detach` / `release` 归还。持有期间宿主**完全停掉**自己的自主行为（走神台词、补水与久坐提醒、困倦入睡），因为两个决定者共用一个角色会得到一只自相矛盾的宠物 |
| `menu:register` | `menu.register` / `menu.unregister` | 在星盘菜单里挂自己的菜单项（宿主渲染）。`menu.unregister` 把它们卸掉。**一个 app 最多同时挂 8 项**，超出的按优先级淘汰最低的一条 |
| `panel:open` | `panel.open` / `panel.update` | 在伴生舱里开一个自己的面板，并把面板上的操作事件回发给插件 |
| `hud:draw` | `hud.draw` / `hud.clear` | 在全屏 HUD 标注层画框（`box`）或箭头（`arrow`），以及清掉自己的标注 |

**权限名和总线方法名不是一回事。** `pet.say` 与 `speak` 是同一个方法的两个名字，但只对应
`pet:speak` 一个权限；`menu.unregister` 与 `menu.register` 共用 `menu:register`；
`hud.clear` 与 `hud.draw` 共用 `hud:draw`。

老式的报文写法 `msg_type: "speak"` 也算 `pet:speak`——换个字段名绕不过权限。

## 权限怎么生效

### 生效权限 = 清单声明 ∩ 用户批准

| 情况 | 生效权限 |
| --- | --- |
| 清单声明了，用户批准了 | 有 |
| 清单声明了，用户没批准 | **没有** |
| 清单没声明 | **没有**（批准表里写了也不生效） |

批准是**按插件逐项**给的：插件 A 批准了 `hud:draw`，不影响插件 B；插件 A 批准了 `pet:speak`，
也不影响它自己的 `hud:draw`。

### 批准不是按会话给的

批准状态记在批准表里，**不绑定连接、不绑定进程**：

- 宿主重启后批准仍然有效。
- 换一条连接、换一个外部程序连同一台宿主，权限一样。
- 真正的凭据是「app_id 对应的权限表」，不是令牌、不是连接。

### 批准表在哪、长什么样

批准结果存在**批准表**里。**目前有两处来源，写入方与读取方各认一处**：

| 位置 | 谁写 | 谁读 |
| --- | --- | --- |
| `config/settings.yaml` 的 `host.plugin_approvals` | **伴生舱插件页签点批准时写这里** | 宿主（启动时交给总线） |
| `plugins/approvals.json` 或 `%APPDATA%\com.aipets.microkernel\plugin-approvals.json` | 手写或脚本生成 | `scripts/doctor.py`、`scripts/plugin-harness.py` |

两种写法：

`config/settings.yaml`：

```yaml
host:
  plugin_approvals:
    demo_external: ["pet:speak", "hud:draw"]
    hello_pet: ["pet:speak"]
```

`plugins/approvals.json`：

```json
{
  "version": 1,
  "plugins": {
    "demo_external": ["pet:speak", "hud:draw"],
    "hello_pet": ["pet:speak"]
  }
}
```

> ⚠️ **两处不一致时，自检脚本会说「未批准」。** 在页签上点过开关之后，
> `config/settings.yaml` 里才有记录；`plugins/approvals.json` 还是旧的那份。
> 要让两边一致，两处都写上同一份内容。

### 未登记的外部程序只有最小默认权限

任何连上总线但**没有登记过**的 app_id，权限表里只有一项：

```text
pet:speak
```

也就是说，未登记的外部程序能说话，但画不了 HUD、开不了面板、挂不了菜单项、拿不到角色决定权。
想拿更多，就得登记成插件：放一份 `plugins/<id>/plugin.yaml`，写清要申请什么。

> ⚠️ **登记过的 app_id 一项都不默认给。** 批准表里列了 `demo_external`，它就**只**有批准表里
> 那些权限——连 `pet:speak` 都不会自动补上。批准表里没有它，它就是一项都不能做。

### 越权调用会被拒绝

Rust 总线在**方法分发之前**检查这张表，被拒的报文回：

```json
{"status": "error", "reason": "权限不足：app「demo_external」调用方法「hud.draw」，需要权限「hud:draw」，该 app 当前被批准：pet:speak"}
```

原文格式是：

```text
权限不足：app「{app_id}」调用方法「{方法}」，需要权限「{权限}」，该 app 当前被批准：{已批准的权限，用、分隔}
```

三条附注：

- 这个 app 一条权限都没有时，末尾写的是 `该 app 当前被批准：未批准任何权限`。
- 调的是**不在总线允许清单内**的方法时，那一段变成
  `该方法不在总线允许清单内、没有对应权限`——**不认识的方法被拒绝，而不是被忽略**。
- 每次拒绝都会在宿主日志里留一行：`[ws_server] 拒绝总线调用：{原因}`。

被拒的方法**不会留下任何副作用**：菜单不会挂上，HUD 不会画，租约不会取得。

> 令牌与权限是两回事。令牌证明「这个连接是本机上的客户端」，权限决定「它能做什么」。
> 插件本体照旧要读 `.pet_ws_token`，但它能不能画 HUD，看的是权限表。

## 插件能做什么与不能做什么

### 插件只描述，宿主负责渲染

插件能放进来的东西只有五类，全是**数据**：

| 类别 | 插件描述什么 | 宿主怎么渲染 |
| --- | --- | --- |
| 气泡 | 一段文本、时长、优先级 | 用宿主的语音气泡组件，带打字机与音频频谱 |
| 动作 | 动作名、表情、台词、时长 | 用宿主的动作队列与优先级规则排队播放 |
| HUD 标注 | 框或箭头的坐标、颜色、标签、倒计时 | 用宿主的全屏标注层，恒为鼠标穿透 |
| 菜单项 | 标题、层级、动作 | 用宿主的星盘菜单，外部项边框是绿的 |
| 面板控件 | 八种 SDUI 控件组成的树 | 用宿主的通用控件渲染器 |

**插件不能自己画界面。** 插件是一个外部程序，它没有自己的窗口，没有自定义 HTML，没有 CSS，
没有前端脚本，也没法往宿主窗口里注入东西。面板是一棵控件树，宿主按 `type` 渲染；
插件给的是「一个开关、一个滑块」，不是像素。

### 不能通过菜单执行任意命令

**经总线注册的菜单项**，`action.type` 只允许四种：

| `action.type` | 作用 |
| --- | --- |
| `emit` | 发一个事件。内部事件会真的改变桌宠状态，外部事件经总线转发 |
| `panel` | 打开伴生面板 |
| `url` | 打开一个链接 |
| `open` | 打开本地路径或应用 |

`exec`（启动本地命令）**会被拒绝**，报：

```text
菜单动作被拒：app「{app_id}」注册的菜单项「{菜单项 id}」的动作类型「exec」不在允许范围，总线注册的菜单只允许 emit / panel / url / open
```

理由很直接：菜单项是**用户点**的，外部程序注册一个再等用户点一下，就能执行任意命令——
那等于把命令执行权发给每一个知道令牌的本地程序。宿主自己的 `pet.yaml` 菜单里确实有 `exec`，
但那份清单是使用者自己写给自己的，不经总线。

**没有写 `type` 的动作同样被拒**（报里写的是 `（未指定）`）——说不清是什么的动作，没法被证明无害。

> 界面这一侧还会再拦一次：带 `exec` 的菜单项**根本不会出现在星盘里**，控制台打一行
> `[menu] 外部菜单项 [菜单项 id] 声明了 action.type=exec，已忽略：外部程序不得通过菜单执行命令。`

**菜单项有上限。** 同一个 app 在星盘里最多同时挂 **8 项**；超出的会淘汰优先级最低的那一条
（优先级相同时淘汰注册得最早的那条），控制台打一行：

```text
[menu] 外部程序 [app_id] 的菜单项超过 8 条上限，已淘汰优先级最低的一条：[菜单项 id]（priority=N）
```

菜单项可以带 `priority`（数字，**大的排在前面**）来抢位置——星盘就一圈，外部程序占满了就没别人的位置了。

### 拿不到 API Key

插件要用大模型，走**宿主配好的通道**：伴生舱 → 🌐 网页与AI脑桥 里配的协议、地址、模型、Key。
密钥不经过插件，插件也读不到、改不了。

- 插件能做的：让桌宠说一句预先准备好的话，或者请求宿主按当前配置去问一句模型。
- 插件不能做的：读 Key、填 Key、换模型、把 Key 带走。

### 权限是一个封闭集合

能申请的只有上表那六项。写一个不认识的权限名，**整份清单不算数**（不是忽略那一条）——
否则用户看到的权限列表就会比插件真正要的短，批准下来的东西和插件想用的东西对不上。

## 调试

两个脚本都**只读文件**，不下载依赖，也不改任何东西。

### `python scripts/doctor.py`

体检宿主与全部插件，分五段：总线令牌、总线端口、配置、插件清单、权限批准。
每条失败都带一句能照着做的修复建议。

```bash
python scripts/doctor.py
```

实际输出（示例）：

```text

         令牌：pet_tk_651c2…0f33（前缀与长度都对）

```

**退出码**：有失败项是 1，没有失败项是 0（警告不影响退出码）。

第 2 段查的是「端口有没有在监听」——**必须先把桌宠宿主跑起来**，否则这一段必然失败，
与插件本身无关。

两个可选参数：

```bash
python scripts/doctor.py --approvals plugins/approvals.json   # 指定批准表
python scripts/doctor.py --plugins-dir E:/AI/my-plugins        # 指定插件根目录
```

### `python scripts/plugin-harness.py plugins/<id>`

单个插件的夹具：读清单、逐条校验、把「声明的权限」与「已批准的权限」对齐，再**离线模拟**
每个总线方法会被放行还是拒绝（不连总线，不改宿主状态）。

```bash
python scripts/plugin-harness.py plugins/demo_external
```

实际输出（示例）：

```text
插件夹具 · demo_external
清单：plugins\demo_external\plugin.yaml
YAML 解析：PyYAML 6.0.3
id：demo_external    版本：1.0.0    名称：外部示例插件 · 提示气泡
说明：往桌宠气泡和 HUD 上放一条外部说明，用来验证插件体系是否打通。

插件会向宿主申请什么（声明的权限）：
  pet:speak      把一句外部提示交给桌宠的气泡显示——只给文字，界面由宿主画。
  hud:draw       给出一条 HUD 标注的位置与文字，由宿主画成矩形和标签。

用户批准了什么（E:\AI\AI-Pets\plugins\approvals.json）：
   pet:speak
   hud:draw

实际生效什么（声明 ∩ 批准）：
  pet:speak
  hud:draw

总线方法判定（离线模拟，没有连总线）：
  pet.act           需要 pet:act        拒绝（没有声明 pet:act） —— 让宠物演一段动作并说话
  pet.say           需要 pet:speak      允许（已声明且已批准） —— 弹语音气泡（speak 是同一个方法）
  pet.driver        需要 pet:driver     拒绝（没有声明 pet:driver） —— 取得／归还角色决定权
  menu.register     需要 menu:register  拒绝（没有声明 menu:register） —— 注册外部菜单项
  menu.unregister   需要 menu:register  拒绝（没有声明 menu:register） —— 注销外部菜单
  panel.open        需要 panel:open     拒绝（没有声明 panel:open） —— 打开伴生面板
  panel.update      需要 panel:open     拒绝（没有声明 panel:open） —— 向伴生面板推送状态
  hud.draw          需要 hud:draw       允许（已声明且已批准） —— 画屏幕标注
  hud.clear         需要 hud:draw       允许（已声明且已批准） —— 清除屏幕标注

结论：清单合法（退出码 0）
```

**退出码**：清单非法是 1，合法是 0。

参数：插件目录（`plugins/demo_external`）或插件 id（`demo_external`）都行，
再加 `--approvals <路径>` 指定用哪张批准表。想看「没批准会怎样」，写一张空的批准表跑一遍：

```bash
python scripts/plugin-harness.py plugins/demo_external --approvals my-approvals.json
```

`pet.say` / `hud.draw` 会从「允许」变成「拒绝（已声明，但用户还没批准）」，其余方法一律拒绝。

> 夹具给的是**离线推断**，真正的放行与否由运行中的宿主裁定。

## 写一个真能跑的插件

### 仓库自带的示例：`plugins/demo_external/`

```text
plugins/demo_external/
├── plugin.yaml   清单：身份、版本、申请的权限与理由
├── plugin.py     插件本体：连总线、发两条消息
└── README.md     这个插件自己的说明
```

它的清单（`plugins/demo_external/plugin.yaml`，**注意它用的是表写法**，
与[上面说的宿主写法](#自检脚本多认的那几种写法)有一处差别）：

```yaml
id: demo_external
name: 外部示例插件 · 提示气泡
version: 1.0.0
description: 往桌宠气泡和 HUD 上放一条外部说明，用来验证插件体系是否打通。
author: AI-Pets
entry: plugin.py
permissions:
  - permission: pet:speak
    reason: 把一句外部提示交给桌宠的气泡显示——只给文字，界面由宿主画。
  - permission: hud:draw
    reason: 给出一条 HUD 标注的位置与文字，由宿主画成矩形和标签。
```

想让它在伴生舱插件页签里正常出现，把 `permissions` 改成字符串列表即可：

```yaml
permissions:
  - pet:speak
  - hud:draw
```

它只做两件事，两件都是「描述」：

| 总线方法 | 权限 | 插件给的 | 宿主画的 |
| --- | --- | --- | --- |
| `pet.say` | `pet:speak` | 一句话 | 桌宠的气泡 |
| `hud.draw` | `hud:draw` | 位置、尺寸、文字 | HUD 的矩形与标签 |

插件自己不开窗口、不画图、不贴图、不注册菜单、不接管角色——**用不到就不申请**。

真跑一遍（需要先启动桌宠宿主，它会签发令牌并监听 9527 起的端口）：

```bash
python plugins/demo_external/plugin.py
```

它会打印连上的端口和宿主对两条消息的回复。宿主没开时，它会明确告诉你「找不到令牌 /
端口没在监听」，而不是静默失败。

改文字、换标注位置：

```bash
python plugins/demo_external/plugin.py --text "今天也辛苦啦"
```

### 写你自己的

三步：

1. 建目录 `plugins/<id>/`，写 `plugin.yaml`（照上面的清单改）。
2. 写插件本体：它要做的事就是连总线、以插件 id 作为 `app_id` 发消息——令牌从 `.pet_ws_token` 读，
   端口在 `host.ws_port_range` 里找。
3. 跑一遍夹具确认清单合法：

```bash
python scripts/plugin-harness.py plugins/<id>
```

三条容易踩的：

- **`app_id` 必须等于插件 id。** 权限表是按 app_id 查的：写错成别的名字，
  宿主就按「未登记的 app」处理，只有 `pet:speak`。
- **每申请一项权限，就在插件里真的用它。** 用户会逐条看；申请了不用，
  多余的批准只会让插件显得可疑。
- **别申请用不上的权限。** 权限是封闭的六项，申请表之外的写不进去。

## 常见问题

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| 插件页签里看不到我的插件 | `plugins/<id>/plugin.yaml` 不存在，或清单校验没过 | 看页签下方「清单异常」那张卡，它写明了是哪个插件、哪个字段、什么原因 |
| 自检脚本说合法，页签里却只有一条「清单异常」 | 两边的清单写法不一致（最常见：`permissions` 一个写字符串、一个写表） | 以宿主的写法为准：`permissions` 写成字符串列表，见[字段全解](#pluginyaml-字段全解) |
| 插件页签里看不到，但在自检脚本里是好的 | 插件目录没被宿主找到 | 确认目录在仓库的 `plugins/` 下，或在 `host.plugins_dirs` 里声明过；页签右上角的「重新扫描」可以手动重来一次 |
| 自检说清单非法 | `id` 与目录名不一致是最常见的一条 | 报错会写出两边各是什么：`id {值} 与目录名 {目录名} 不一致` |
| 插件在页签里，但某个权限没有开关 | 那个权限没写进清单的 `permissions` | 补上那行；申请了才谈得上批准 |
| 批准了还是没生效 | 生效权限是「声明 ∩ 批准」，批准了但没声明同样不生效 | 对一遍清单与批准表 |
| 总线回 `权限不足：app「x」调用方法「y」…` | 调用超出生效权限 | 要么改清单申请并让用户批准，要么换一个调用 |
| 插件只说了话，画不了 HUD | `hud:draw` 没申请或没批准 | 补申请 + 批准 |
| 外部程序只能说话，画不了 HUD | 未登记的 app_id 默认只有 `pet:speak` | 登记成插件：放一份 `plugins/<id>/plugin.yaml` |
| 登记过的插件连说话都不行 | 登记过的 app **没有默认权限**，只有批准表里那些 | 把 `pet:speak` 加进批准表 |
| 页签上批了，自检脚本却说「未批准」 | 两处批准表来源不一致（页签写 `config/settings.yaml`，脚本读 `plugins/approvals.json`） | 两处都写上同一份内容，见[权限怎么生效](#权限怎么生效) |
| 菜单项被拒，报 `菜单动作被拒：…` | 菜单动作类型不在 `emit / panel / url / open` 里 | 改动作类型；`exec` 一律不行 |
| 我想给插件一个自己的界面 | 插件不能注入 HTML 或脚本 | 用面板控件：八种 SDUI 控件，宿主渲染 |
| 插件想调大模型 | 插件拿不到 Key | 走宿主配好的通道（伴生舱 → 🌐 网页与AI脑桥） |
| 批准要不要每次重来 | 不用 | 批准按插件逐项给，不按会话，宿主重启后仍然有效 |
| 改了清单没反应 | 宿主要重新扫描 `plugins/` 目录才会读到新内容 | 页签右上角的「重新扫描」；多数情况下保存即生效 |
| 插件在自己机器上能跑，换台机器不行 | 令牌、端口区间或依赖没跟过去 | 插件目录是自包含的：整个拷过去，别只拷 `plugin.yaml` |
| 插件能不能要更多权限 | 不能凭空要 | 权限表是封闭的六项；写不认识的权限名，整份清单不算数 |
